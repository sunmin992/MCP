# 근거 검사(GUARD) — 시뮬레이터 제공자와 클라이언트를 위한 안내

LLM 이 사용자 발화를 요구·입력값으로 옮길 때, 옮긴 값마다 근거가 된 발화 구절을 함께 받고 서버가 대조한다.
판정 규칙은 공통 모듈 `mcp-common`의 `com.wastesim.evidence` 하나뿐이다. 브로커와 모든 시뮬레이터 제공자가 같은 규칙을 쓴다.

## 어디서 검사하나

| 위치 | 검사 대상 | 조건 |
|---|---|---|
| 브로커 `find_simulators` | `requirements`의 지역 · 기간 · 해상도 · 지표 · 수치 조건 | 클라이언트가 `userUtterances`를 보낼 때. 어긋나면 매칭 전에 돌려보낸다(조정 횟수를 쓰지 않음). 응답의 `requirementEvidence.status`: VERIFIED / PARTIAL / NOT_CHECKED |
| 시뮬레이터 `build_scenario` 등 | 서브태스크 답변값(USER 출처 값, 조건부 결정의 기본값) | 클라이언트가 `userUtterances`를 보낼 때 |

## 판정 규칙

| 대상 | 통과 | 막음 | 판단 보류(unverified) |
|---|---|---|---|
| 모든 USER 값 | 근거 구절이 발화에 있음 | 구절이 없거나 발화에 없음 | — |
| 수치 | 구절의 숫자가 **선언된 단위**로 바꿔 값과 같음 | 값이 다름 / 숫자 뒤의 단위말이 이 필드의 것이 아님 | 숫자로 바꿀 수 없는 표현("며칠", "여러 대") |
| 선택지 | 구절에서 가장 길게 맞는 표현이 제출 값의 것 | 가장 길게 맞는 표현이 다른 값의 것 | 맞는 표현이 없음, 표현을 선언하지 않음 |
| 조건부 결정의 기본값 | 동의 구절("기본값으로")이 발화에 있음 | 동의 구절 없음 | — |
| 요구의 지표(requiredOutputs) | 구절이 발화에 있음 | 구절 없음 | 어떤 지표로 옮겼는지가 맞는지는 늘 보류 |

단위 바꿈(`UnitEvidence`): minute(시·시간 → 분, 오전·오후), day(주 → 일), ratio(% → 비율), kg(톤 → kg), won(천원·만원 → 원).
필드 이름(…Minutes, days, …Share)으로 단위를 짐작하지 않는다. 단위를 선언하지 않은 필드는 숫자를 그대로 비교한다.

## 제공자가 템플릿에 선언할 것

새 시뮬레이터는 Java 코드 없이 템플릿(또는 SES 결정)에 아래 칸을 적으면 같은 검사를 받는다. 모두 선택 항목이다.

```json
{
  "answerKey": "busCount", "valueType": "INTEGER",
  "unit": null,
  "unitWords": ["대"]
},
{
  "answerKey": "headway", "valueType": "INTEGER",
  "unit": "minute"
},
{
  "answerKey": "busType", "valueType": "ENUM", "allowed": ["ARTICULATED", "STANDARD"],
  "valueTerms": {"ARTICULATED": ["굴절", "굴절버스"], "STANDARD": ["일반", "일반버스"]}
}
```

- `unit`: 값의 단위. 위 표의 단위면 바꿔 보고, 그 단위의 말(분·시간, 일·주, % …)을 이 필드의 단위말로 인정한다.
- `unitWords`: 개수를 셀 때 붙는 말. 구절의 숫자 뒤에 다른 단위말(예: 건물 수에 "대")이 붙어 있으면 다른 항목의 값으로 보고 막는다.
- `valueTerms`: 선택지 값마다 사용자가 쓰는 표현. 부정 표현은 긍정 표현보다 길게 적는다("반영하지" vs "반영") — 가장 긴 표현이 이긴다.

제공자 코드에 필요한 것은 템플릿을 `EvidenceField`로 바꾸는 연결 함수 하나다(예: `parking-sim/.../mcp/ses/EvidenceGuard.java`, 30줄 안팎).
시뮬레이터마다 템플릿 클래스 이름 · 생성 조건 표현이 달라도 이 함수만 맞추면 된다.

## 현재 선언 현황

| 제공자 | 단위 선언 | 단위말 | 선택지 표현 |
|---|---|---|---|
| 장량동 블록 폐기물 | 분(4) · 일 · 비율 · kg(2) | 건물 · 차량 · 세대 · 반복 | 차종 · 교통 반영 · 구역 배정 |
| 주차 | 분(3) · 일 · 원 · 비율(2) | 주차장 · 면수 · 도착 · 반복 | 요금 정책 · 혼잡 반영 |
| 민원 창구 | 분(2) · 일 · 비율 | 창구 · 방문자 · 반복 | 예약 반영 · 대기열 방식 |
| 구 단위 폐기물 | 분(3) · 일 | 구역 · 세대 · 차량 · 반복 | 차종 |

## 한국어 수 표현

대조 전에 발화와 근거 구절을 같은 규칙(`KoreanNumbers.normalize`)으로 숫자 표현으로 바꾼다. 원문은 바꾸지 않고 비교할 때만 쓴다.

| 표현 | 바뀐 꼴 |
|---|---|
| 하루 · 이틀 · 사흘 … 열흘 · 보름, 일주일 | 1일 · 2일 · 3일 … 10일 · 15일, 1주 |
| 고유어 수 + 단위: 두 대 · 세 번 · 열두 곳 · 스무 명 · 한 시간 | 2대 · 3번 · 12곳 · 20명 · 1시간 |
| N시간 반 | N.5시간 (한 시간 반 → 90분) |
| 1만 5천원 | 15000원 |
| 정오 · 자정, 밤 · 저녁 · 새벽 N시 | 낮 12시 · 밤 12시, 시각을 오전/오후로 바꿔 분으로 |

낱말 일부가 수처럼 보이는 경우는 바꾸지 않는다: 단위 앞이 한글이면 바꾸지 않고(보름달 · 한동안 · 두부), 단위 뒤에 한글이 이어지면 조사일 때만 바꾼다.
"세대"는 가구 뜻으로 보고, 띄어 쓴 "세 대"만 3대로 본다. 같은 결과를 다시 넣어도 그대로다.

## 발화 자체의 진위

근거 검사는 "LLM 이 넘긴 발화"와 "LLM 이 낸 값"이 서로 맞는지만 본다. 발화도 LLM 이 넘기므로, 발화를 지어내고 값을 거기에 맞추면 통과한다.
그래서 발화의 진위는 사람이 확인한다 — 확인 화면이 발화와 해석을 나란히 보여 주고, 사람이 맞다고 체크해야 승인된다.
근거 검사의 몫은 LLM 의 **비의도적 해석 실수**를 잡는 것으로 한정한다.

## 한계

- 검사는 "근거가 실제로 있고, 수와 단위와 표현이 맞는가"까지다. 해석이 의미상 맞는지(예: "효율"을 어떤 지표로 옮길지)는 판단하지 못한다 — 확인 화면의 사람 승인과 해석 정확도 측정(R1)이 맡는다.
- 클라이언트가 발화 목록을 보내지 않으면 검사하지 않고 NOT_CHECKED 로 표시한다.
- 단위 바꿈과 표현은 한국어 중심이다. 다른 언어는 `UnitEvidence`의 단위말과 템플릿의 표현을 추가해야 한다.
- 숫자로 바꿀 수 없는 표현("며칠", "몇 대", "여러 번")은 판단하지 못한 것으로 남긴다. 붙여 쓴 "세대"는 차량 3대로 읽지 않으므로, 사용자가 "차 세대로"라고 붙여 쓰면 판단 보류가 된다.
