# 지역명으로 가상 시나리오 구성하기

"덕명동 시뮬레이터 실행해줘" 또는 "아무 동네 시뮬레이터 실행해줘"를 공통 기본값으로 처리한다.
도메인은 생활폐기물 수거이며, 지역명은 입력 조건이다. 지역마다 새 시뮬레이터 서버나 Java 클래스를 만들지 않는다.

## 동작 흐름

1. MCP 클라이언트 LLM이 사용자 발화에서 도메인과 지역명을 추출한다.
2. 브로커 find_simulators에 requirements.regionId를 전달한다. 해당 지역 데이터가 등록되어 있지 않아도
   ASSUMED_BLOCK_FOR_ANY_LABEL 정책을 가진 제공자는 조건부 후보가 된다.
3. 선택된 제공자의 create_neighborhood_scenario에 요청 원문과 selection을 전달한다.
4. 제공자는 기존 지역 데이터가 있으면 그것을 참조하고, 미등록 지역은 genericProfile의 공통 가상 블록으로 구성한다.
5. 사용자 지정 값과 필수 조건을 먼저 적용하고, 남은 필수 결정만 제공자 템플릿 기본값으로 채운다.
   생성 조건이 거짓인 결정은 채우지 않는다. 차종에 따라 달라지는 가용 적재량은 기존 planner.defaultFor 규칙을 따른다.
6. Task·설정·목적·지역 제약 검증을 거쳐 UNCONFIRMED로 저장하고 confirmUrl을 반환한다.
7. 사용자가 확인 화면에서 가정과 설정을 승인하면 get_scenario_status로 토큰을 조회하고 run_scenario_by_token으로 실행한다.

시나리오 생성 도구는 실행하거나 승인하지 않는다. 검증 성공도 사용자 승인을 대신하지 않는다.

## 호출 예

브로커:

```json
{"domain":"쓰레기수거","requirements":{"regionId":"덕명동"}}
```

선택 이후 제공자 호출:

```json
{"request":"덕명동 시뮬레이터 실행해줘","regionName":"덕명동","selection":{"설명":"실제 브로커 응답의 selection 객체를 그대로 전달"}}
```

위 selection 표기는 설명용이다. 실제 호출에는 브로커가 반환한 schemaVersion/matchId/serverId/cardDigest/requirements를 그대로 넣는다.
selection 안에 지역이 있으면 regionName을 다시 적지 않아도 된다. 선택 당시 지역과 명시한 지역이 다르면 재매칭을 요구한다.

직접 제공자 호출도 가능하다.

```json
{"request":"아무 동네 시뮬레이터 실행해줘"}
```

지역 미제시 시 "가상 동네"가 된다. 특정 입력만 바꾸려면 values에 템플릿 답변키를 넣는다.

```json
{"request":"덕명동에서 건물 8개와 차량 2대로 이틀간 실행해줘","regionName":"덕명동","values":{"numBuildings":8,"truckCount":2,"days":2,"seeds":1}}
```

기본 실행은 RUN 목적의 설정 한 벌이다. 비교 실험은 기존 plan_subtasks/build_scenario 경로를 사용한다.
입력값이 범위를 벗어나면 기본값으로 덮어쓰지 않고 NEEDS_INPUT과 missingInputs를 반환한다.
기본값이 없는 추가 결정이 활성화돼도 사용자에게 필요한 질문을 반환한다.

## 기본값과 한계

- 미등록 지역의 기본 규모는 건물 4개, 건물당 25명인 가상 블록이다. 그 밖의 기간·반복·차량·수거 조건은 서버 템플릿을 따른다.
- 기본값 출처는 MODEL_DEFAULT로 남고 확인 화면에 표시한다. 요청에서 지정한 값은 해당 출처와 근거 검사 상태를 유지한다.
- 지역명은 사용자 라벨이며 지오코딩하거나 실제 행정구역을 확정하지 않는다.
- 다른 지역의 실제 지리·인구·도로·교통을 수집하거나 재현하지 않는다. 결과는 가정에 따른 모델 실행이다.
- 미등록 지역은 상수 이동 모드와 논문 기준선 배출 모델을 쓴다. 장량동 교통·좌표·차량 진입 제한이나 포항 전용 배출 조건을 가져오지 않는다.
- 현재 블록 모델의 건물 수 상한은 26개다. "덕명동 전체"나 실제 도로망을 요구하면 같은 이름의 가상 블록으로 슬쩍 축소하지 않는다.
  브로커의 공간 규모 판정 및 제공자 범위 검증을 따른다.
- 장량동 기반 SES ID와 serverId는 기존 MCP 연결 호환성을 위해 유지했다. 이것이 다른 지역의 실측 자료 사용을 의미하지 않는다.

## 설정 및 검증

`simulator/src/main/resources/regions/catalog.json`의 genericProfile이 미등록 지역 정책과 공통 지역 입력을 정의한다.
프로파일 변경은 제공자 리소스 식별값 변경으로 감지되어 기존 검증과 승인이 무효화된다. 서버 재시작 후 재구성·재승인한다.
새 지역명마다 카탈로그 항목을 추가할 필요는 없다. 실제 데이터가 확보된 지역은 별도 검증된 제공자 데이터·어댑터로 확장해야 한다.

두 서버를 새 빌드로 재시작한 뒤 다음 스크립트로 미승인 통합 흐름을 확인할 수 있다.

```powershell
python scripts/demo_neighborhood_flow.py
```

실제 자연어 추출 성능은 사용하는 MCP 클라이언트 LLM에 달려 있다. 서버가 모든 자유 발화를 자체 해석한다는 의미는 아니다.
