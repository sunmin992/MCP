# R1 오류 주입: 틀린 해석을 서버가 잡는가

2026-11-05. [해결 설계](../../resolution-design-2026-11-03.md) R1 작업 3. 실행기: `scripts/run_error_injection.py`, 원자료: [error-injection.json](error-injection.json).

## 방법

- **기준 해석:** Ollama 추출 평가([30b](../model-evaluation-ollama-qwen3-coder-30b/), [7b](../model-evaluation-ollama-qwen2.5-7b/))에서 정답과 정확히 일치한 모델 출력. 실제 근거 구절(evidence)을 갖고 있다. 28개 사례 중 17개에 있다. 나머지 11개(E01·E02·E05~E08·E20~E23·E28)는 정확 일치 출력이 없어 빠졌다. 지역명이 든 사례가 모두 여기에 속한다.
- **주입:** 기준 해석에 오류 하나를 넣는다. 근거 구절은 모델이 실제로 하던 방식대로 둔다(값만 바꾸고 구절은 그대로, 지어낸 항목은 발화 전체를 구절로).
- **경로:** 브로커 `find_simulators`(근거 검사 + 조건 판정) → 장량동 `create_neighborhood_scenario`(구성·검증). 구성 단계에서 묻는 결정에는 사용자가 "나머지는 기본값으로 해줘"라고 답한 것으로 둔다. 승인·실행은 하지 않는다.
- **판정:** 같은 사례의 기준 해석 결과와 비교한다.
  - 잡힘: 근거 검사 거절(CAUGHT_EVIDENCE), 기준은 후보가 있는데 후보 없음(CAUGHT_NO_CANDIDATE), 구성 거절(CAUGHT_BUILD)
  - 놓침: 거절돼야 할 요청이 후보를 얻음(MISSED_ACCEPTED), 후보 집합이 바뀜(MISSED_OTHER_CANDIDATES), 같은 후보에서 다른 설정이 유효로 통과(MISSED_CONFIG)
  - 무해: 기준과 같은 결과
  - 구성 미검사: 후보가 주차·민원 창구·북구뿐이어서 구성 단계를 자동으로 돌리지 못함. 이 셋은 에이전트가 값을 채워 `build_scenario`를 불러야 한다.

## 결과

주입 63건(17개 사례). 무해 11건과 구성 미검사 4건을 빼면 영향이 있는 오류 48건 중 **35건(73%)을 실행 전에 잡았고 13건을 놓쳤다.**

| 오류 유형 | 잡힘 | 놓침 | 무해 | 미검사 |
|---|---|---|---|---|
| 기간 단위 바꿈 (사흘 → 3주) | 8 | 0 | 0 | 0 |
| 수치 바꿈 (값 +1) | 14 | 0 | 0 | 0 |
| 기간을 해상도로 혼동 | 6 | 0 | 2 | 0 |
| 말하지 않은 기간 추가 | 6 | 1 | 2 | 0 |
| 말하지 않은 결과 지표 추가 | 1 | 3 | 6 | 0 |
| 결과 지표 누락 | 0 | 3 | 1 | 3 |
| 필수 → 선호 강등 | 0 | 5 | 0 | 1 |
| 선호 → 필수 승격 | 0 | 1 | 0 | 0 |
| 지역 누락 | 기준 사례 없음 |||||

- 수치·단위 오류는 모두 근거 검사에서 막혔다. 한국어 수 표현 대조(사흘, 일주일, 2주)가 작동한다.
- 기간을 해상도로 바꾼 오류는 해상도를 선언한 카드가 없어 후보 없음으로 끝났다.
- "말하지 않은 결과 지표 추가" 무해 6건 중 4건(E10·E15·E17·E19)은 기준도 거절된 사례이고, 2건(E04·E09)은 추가된 "평균 민원 수"가 장량동의 기본 관측 지표와 같아 설정이 바뀌지 않았다.

## 놓친 13건의 원인

**1. 근거 구절에 숫자가 없으면 검사하지 못하고 통과시킨다 (4건)**
근거 검사는 구절의 수·단위를 대조할 수 없으면 그 항목을 `PARTIAL`(미확인)로 표시만 하고 막지 않는다.
- E12 "평균 운행 소요 시간을 보고 싶어"에 기간 1주를 지어내고 발화 전체를 근거로 댔다 → MATCH, 7일 설정이 유효로 통과.
- E03·E18·E24: 지표를 지어내고 발화 전체를 근거로 댔다 → 북구 후보가 빠짐.

**2. 선호와 필수의 구분을 검사하지 않는다 (6건)**
"가능하면/반드시" 같은 표현이 근거 구절에 있어도 그 조건이 선호인지 필수인지는 대조하지 않는다.
- E19 "반드시 101회 반복"을 선호로 강등 → 카드 범위(최대 100회)를 넘는데도 후보 둘을 얻음.
- E10 "건물 27개인 블록"(최대 26개)을 선호로 강등 → 장량동 후보를 얻음.
- E09·E24는 같은 후보에서 다른 설정으로, E25는 다른 후보 집합으로 통과.
- E18 "가능하면 10회"를 필수로 승격 → 같은 후보에서 다른 설정. 30b 평가의 E20 사례와 같은 유형이다.

**3. 결과 지표가 빠지면 거절돼야 할 요청이 통과한다 (3건)**
- E26 "탄소 배출량", E13 "수거일당 남은 폐기물량"은 지표 때문에 거절되거나 북구만 후보였다. 지표를 빼면 다른 조건이 없어 후보 둘이 나온다.
- E12는 지표를 빼면 북구가 후보에 추가된다.
- 지표 누락은 근거가 필요한 항목이 사라지는 것이라 근거 검사로는 원리상 잡을 수 없다. 확인 화면에서 발화와 해석을 나란히 보는 사람만 잡을 수 있다.

## 보완 후보

1. **근거 미확인을 차단으로:** 수·단위가 필요한 항목(기간, 해상도, 수치 조건)이 `PARTIAL`이면 MATCH 대신 질문(ADJUST_REQUEST)으로 돌린다. 원인 1의 기간 사례를 막는다. 지표 사례는 지표 이름 대조가 필요하다.
2. **선호·필수 표지 대조:** 근거 구절에 "가능하면/좋겠어"가 있는데 필수 조건이거나, "반드시/꼭"이 있는데 선호 조건이면 거절한다. 원인 2의 6건을 막는다.
3. **누락은 확인 화면에서:** 원인 3은 서버가 잡을 수 없다. 확인 화면이 발화의 구절 중 해석에 쓰이지 않은 부분을 강조하면 사람이 볼 수 있다.

## 보완 1·2 구현 후 재측정

`RequirementEvidence`(mcp-common)를 바꿨다.
- **보완 1:** 기간·해상도·수치 조건의 근거 구절에 수가 없으면 미확인(PARTIAL)으로 넘기지 않고 막는다. 한국어 수 표현("이틀", "일주일")은 전처럼 숫자로 바꿔 본다.
- **보완 2:** 선호 조건의 구절에는 "가능하면 · 가급적 · 되도록 · 좋겠" 같은 선호 표현이 있어야 하고, 필수 조건의 구절에는 없어야 한다. 추출 프롬프트의 규칙("가능하면/좋겠어는 preferences, 그 밖은 constraints")과 같은 기준이다.

결과 지표 이름 대조는 이번에 넣지 않았다. 변경 전 결과는 [error-injection-before.json](error-injection-before.json)에 있다.

| | 변경 전 | 변경 후 |
|---|---|---|
| 잡힘 | 35 | **45** |
| 놓침 | 13 | **6** |
| 무해 | 11 | 9 |
| 구성 미검사 | 4 | 3 |
| 영향이 있는 오류 중 잡힌 비율 | 35/48 (73%) | **45/51 (88%)** |

- 무해 2건(E13·E26에 기간 추가)은 기준도 거절되는 사례라 전에는 무해였고, 이제는 근거 검사에서 먼저 막힌다.
- 남은 놓침 6건은 지표 추가 3건(E03·E18·E24)과 지표 누락 3건(E12·E13·E26)이다. 앞의 원인 1 중 지표 사례와 원인 3이다.
- 필수/선호 바꿈 7건(구성 미검사였던 E27 포함)과 숫자 없는 구절로 기간을 지어낸 E12는 모두 근거 검사에서 막힌다.

**맞는 해석을 막지 않는지:** 같은 브로커로 Ollama 두 모델의 추출 결과를 다시 채점했다.
- 정확 일치 해석(30b 44회, 7b 21회) 가운데 새로 막힌 것은 없다. 7b의 E11·E25는 변경 전에도 막혔다. E11은 0일 기간 검증 때문이고, E25는 모델이 근거 키를 `constraints`로 잘못 적었기 때문이다.
- 30b가 E20 "가능하면 건물 8개"를 필수로 옮겨 후보가 줄었던 2건(WRONG_REACHED_OTHER_CANDIDATES)은 이제 근거 검사에서 막힌다. 30b에서 다른 후보로 이어진 틀린 해석은 0건이 됐다.
- 테스트: mcp-common 20개, broker 161개 통과.

## 한계

- 기준 사례 17개, 오류 유형 9개, 오류는 한 번에 하나만 넣었다. 실제 LLM은 여러 오류를 함께 낸다.
- 구성 단계는 장량동만 자동으로 검사했다. 주차·민원 창구·북구 후보 4건은 미검사로 남겼다.
- 오류 주입은 작성자가 설계한 것이다. 실제 모델 오류 분포와 다르다. 실제 모델 오류의 결과는 추출 평가의 `outcomes`에 있다.
- 구성 단계의 미답변 결정은 모두 "기본값으로"로 답했다. 사용자가 다른 값을 답하는 경우는 보지 않았다.
