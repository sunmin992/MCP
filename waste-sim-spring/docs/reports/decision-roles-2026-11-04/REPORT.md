# 시뮬레이터 구성 결정의 역할 분류와 처리 방식 비교

2026-11-04. 연구 주장을 "사용자가 몰라도 된다"에서 다음으로 바꾸기 위한 근거다.

> 사용자는 시뮬레이터 구조를 몰라도 되지만, 자신의 의도에 해당하는 결정은 직접 내려야 한다.
> LLM 은 말해진 조건을 옮길 수 있지만 말하지 않은 의도를 채우면 안 된다.
> 시스템은 결정을 역할로 나눠, 정할 수 있는 것은 정하고 사용자만 정할 수 있는 것은 사용자에게 돌린다.

원자료: [results.json](results.json). 실행:

```powershell
.\mvnw.cmd -B -pl simulator -am test '-Dtest=DecisionRoleExperiment' '-Dsurefire.failIfNoSpecifiedTests=false'
```

## 1. 결정의 두 축

| 축 | 질문 | 누가 판단 | 어디에 적나 |
|---|---|---|---|
| 구조 | 이 결정이 이번 요청에 **필요한가** | 시스템(생성 조건) | SES `generateWhen` |
| 역할 | 이 결정의 **값을 누가 정할 수 있나** | 제공자가 미리 분류 | SES `decisionRole` · `roleBasis` |

| 역할 | 뜻 | 시스템 처리 |
|---|---|---|
| **INTENT** 의도 | 사용자의 목적 · 정책 · 판정 기준. 정답이 없다 | 말했으면 그대로. 안 말했으면 기본값을 넣되 확인 화면 맨 위에 "당신이 정할 항목"으로 따로 보인다 |
| **DATA** 데이터 | 외부 자료로 정해지는 사실 | 지역 자료로 채우고 출처를 붙인다. 자료가 없으면 "자료가 없어 기본값을 쓴 항목"으로 따로 보인다 |
| **ASSUMPTION** 가정 | 사실로도 의도로도 정할 수 없는 모델링 선택 | 기본값을 쓰고 "모델 가정"으로 표시한다 |

## 2. 장량동 SES 의 분류 (결정 19개)

| 역할 | 수 | 결정 |
|---|---:|---|
| INTENT | 9 | 차량 유형 · 차량 대수 · 배차 간격 · 수거 시각 · 하루 여러 번 수거 시각 · 교통 반영 여부 · 기간 · 반복 횟수 · 민원 기준 |
| DATA | 4 | 건물 수 · 동당 세대 수 · 수거장 용량 · 경로 적재 몫 |
| ASSUMPTION | 6 | 이동시간 계산 방식 · 교통 측정 자료 선택 · 구역 배정 규칙 · 구역 내 이동시간 · 직업 구성 · 배출 시각 모델 |

결정마다 분류 근거(`roleBasis`)를 SES 에 함께 적었다. 템플릿을 만들 때 역할이 없는 결정이 있으면 거절한다.

## 3. 시스템에 반영한 것

- 구조 선택 표(`structureSelection`)의 결정마다 역할을 싣는다.
- 시나리오 생성 응답과 검증 기록에 `decisionRoles`를 싣는다:
  `intentGiven`(사용자가 정함) · `intentDefaults`(**사용자가 정해야 하는데 기본값**) · `dataFromRegion` · `dataGaps`(**자료 없음**) · `assumptions`.
- 확인 화면이 이 순서로 보여 준다: 당신이 정할 항목 → 자료가 없던 항목 → 모델 가정.

## 4. 처리 방식 비교

사용자가 실제로 할 만한 요청 12개에서, 사용자가 말한 결정을 미리 정해 두었다(결과 파일의 `said`).
실제 생성 조건으로 각 요청에 필요한 결정 전체를 구한 뒤, 말하지 않은 결정을 방식마다 어떻게 처리하는지 셌다.
"지역 자료 있음"은 공개 지도 블록(건물 수 · 세대 수 · 수거장 용량을 자료로 채움), "없음"은 가상 블록이다.

| 방식 | 질문 | 확인 항목 | 사용자 모르게 채운 의도 결정 | 자료 없이 채운 데이터 결정 | 표시 없는 가정 |
|---|---:|---:|---:|---:|---:|
| 전부 묻기 | **155** | 0 | 0 | 0 | 0 |
| LLM 이 다 채우기 | 0 | 0 | **71** | 12 (없음 47) | **37** |
| 역할별 확인 (지금 구현) | 0 | 83 (없음 118) | 0 | 0 | 0 |
| 역할별 질문 (의도만 묻기) | **71** | 12 (없음 47) | 0 | 0 | 0 |

12개 요청 합계다. 요청 하나에 말하지 않았지만 필요한 결정이 평균 12.9개(14~16개 중 0~3개만 말함), 그중 의도 결정이 평균 5.9개다.

- **LLM 이 다 채우는 방식의 위험이 숫자로 드러난다.** 요청 하나에 평균 5.9개의 의도 결정(수거 시각 · 차량 대수 · 민원 기준 · 기간 등)이
  사용자가 모르는 사이에 정해진다. 근거 검사(2026-10-30 실험의 47건)가 막으려던 바로 그 경우다.
- **전부 묻기는 부담이 크다.** 요청 하나에 평균 12.9개를 묻는다.
- **의도만 묻기**는 질문을 54% 줄이면서(155 → 71) 사용자 모르게 정해지는 의도 결정을 0으로 만든다.
  데이터 결정은 지역 자료가 있으면 1개(경로 적재 몫)만 남는다.
- 지금 구현(역할별 확인)은 질문 없이 진행하되, 의도 기본값을 확인 화면에서 따로 보여 주는 쪽이다.
  "빨리 돌려 보기"와 "의도를 꼭 확인하기" 사이의 선택이며, 둘 다 사용자 모르게 정해지는 의도를 남기지 않는다.

## 5. 관찰

- **의도 결정이 생각보다 많다.** 장량동 모델에서 19개 중 9개가 의도다. 사용자가 짧게 요청할수록 시스템이 대신 정해야 할 의도가 많아진다.
  이것이 "사용자가 몰라도 된다"가 그대로는 성립하지 않는 이유이고, 주장 전환의 근거다.
- 반복 횟수 · 기간처럼 의도로 분류했지만 합리적인 표준값이 있는 결정이 있다. 이들을 "표준값 있는 의도"로 따로 두면 질문을 더 줄일 수 있다.
- 경로 적재 몫은 데이터 결정이지만 수집 출처가 없어 늘 자료 없음으로 남는다. 운영 기관 자료를 연결하거나 사용자에게 물어야 한다.

## 한계

- 분류는 제공자(작성자)의 판단이다. 같은 결정을 다른 사람이 다르게 분류할 수 있다 — 독립 분류자와의 일치도를 재야 한다.
- 요청 12개와 "사용자가 말한 결정"은 작성자가 정했다. 실제 사용자 발화와 LLM 해석으로 바꾸면 R1 과 합쳐 측정할 수 있다.
- 사람 대상 측정이 아니다. 질문 수 · 확인 항목 수는 부담의 대리 지표이고, 실제 소요 시간이나 만족도는 재지 않았다.
- 장량동 모델 하나에 대한 분류다. 다른 제공자의 결정에도 역할을 붙여야 일반성을 말할 수 있다.
