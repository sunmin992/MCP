# 지역명만으로 공개 지도 블록을 자동 구성하는 실험

2026-11-03. [해결 설계](../../resolution-design-2026-11-03.md)의 R2 구현 결과다.
목표: 사람이 지역 데이터를 미리 넣지 않아도, 사용자가 말한 아무 동네 이름으로 그 지역의 실제 주거 블록을 구성해 실행한다.
사용법과 추정 규칙은 [지역명으로 시나리오 구성하기](../../guides/NEIGHBORHOOD_SCENARIOS.md)에 있다.

## 바뀐 동작

- 이전: 등록되지 않은 지역은 이름표만 바뀐 공통 가상 블록(건물 4동 × 25세대, 구간 15분)이었다.
- 이후: `create_neighborhood_scenario`가 Nominatim → Overpass → OSRM으로 지역을 찾아 실제 주거 블록(최대 26동)을 고르고,
  건물 수·동당 세대 수·구간 이동시간을 지도 자료로 정한다. 값마다 OBSERVED / ESTIMATED / ASSUMED 등급이 붙는다.
- 같은 이름이 여러 곳이면 `NEEDS_REGION`으로 후보를 돌려주고 사용자에게 묻는다. 추측하지 않는다.
- 지역을 못 찾거나, 주거 건물이 모자라거나, 지도 서버에 닿지 못하면 가상 블록으로 내리고 사유를 남긴다.
- 수집한 블록과 조회 원문을 캐시한다. 블록 파일이 바뀌면 지역 식별값 대조에서 이전 시나리오가 막힌다.
- 확인 화면·상태 조회·실행 결과에 `scenarioMode=PUBLIC_DATA_BLOCK`, 자료 등급, 출처 등급표가 남는다.
- 능력 카드의 지역 정책을 `PUBLIC_MAP_BLOCK_FOR_ANY_LABEL`로 바꾸고, 브로커가 이 흐름과 후보 질문을 안내한다.
- 엔진 코드는 바꾸지 않았다. 지역 자료는 기존 입력값과 지역 묶음의 `modelOverrides.routeTravelMinutes`로만 들어간다.

## 실험: 등록하지 않은 이름 13개

요약: 13개 중 6개는 실제 블록으로 구성, 5개는 동명이인이라 질문, 2개는 사유를 남기고 가상 블록으로 내렸다. 잘못된 지역을 고른 사례는 없었다.
동명이인 후보 중 하나를 고른 이름("중앙동 중구 부산광역시")은 한 곳으로 확정돼 구성됐다.
처음 보는 지역의 수집 시간은 29~51초였다. 캐시가 있으면 네트워크 없이 즉시 응답한다.

### 관찰

- **지역에 따라 입력이 실제로 달라진다.** 아파트 블록(덕명동·신림동·부산 중앙동)은 동당 65~111세대, 저층 주택가(연남동·역삼동)는 3~6세대다.
  가상 블록은 지역과 관계없이 4동 × 25세대였다.
- **장량동 대조:** 지도 자료로 추정한 장량동 블록은 동당 33세대다. 기존 장량동 모델의 기준선 25세대와 같은 규모대다.
  추정 규칙을 고치기 전(주택 1세대 고정)에는 27세대였다. 추정 규칙에 따라 값이 움직이므로 세대 수는 ESTIMATED로 둔다.
- **도로 이동의 영향은 작다.** 블록 안 구간 도로 이동은 0.24~0.76분이라, 분 단위 구간 상수(도로 + 정차 가정 12분)에서는 12~13분으로 거의 같다.
  지역 간 결과 차이는 주로 건물 수와 세대 수에서 나온다.
- **OSM 충실도 차이:** 역삼동은 층수 태그가 26동 중 1동이라 세대 수가 대부분 기본 층수로 추정됐다. 농촌(풍천면)은 주거 건물이 거의 없었다.
- **공개 서버 불안정:** 첫 실행에서 Overpass가 502를 세 번 냈다. 재시도(간격을 늘려 최대 3회)를 넣은 뒤에는 모두 성공했다.

## 검증

녹화 응답 테스트 `PublicMapRegionTest` (7건, 네트워크 없음, 실험 당시 응답을 `src/test/resources/regions/osm/`에 보관):

- 덕명동 → 출처 등급이 붙은 실제 블록, 조회 원문 보관
- 생성 도구 → PUBLIC_DATA_BLOCK 시나리오의 실행 설정이 지역 자료와 일치, 미승인 실행 거절, 승인 모사 후 실제 엔진 실행
- 두 번째 요청은 캐시만 사용(네트워크 호출 시 실패하도록 해서 확인)
- 중앙동 → NEEDS_REGION, 후보 목록, 시나리오 미생성
- 없는 지역·네트워크 실패 → 사유가 붙은 가상 블록
- 캐시 블록의 이동시간 변조 → 이전 시나리오의 지역 식별값 불일치, 장량동 교통 허용으로 변조 → 캐시 거부
- 블록 선택이 입력 순서와 관계없이 같고 26동을 넘지 않음

전체 테스트 결과는 [test-summary.md](test-summary.md)에 있다.

## 한계

- 동 전체가 아니라 동 안의 블록 하나(최대 26동)다.
- 세대 수는 건물 형태 추정이며 건축물대장·인구 통계와 대조하지 않았다. 다음 보강 후보다.
- 배출 시간대·교통 혼잡은 지역 자료가 아니다(ASSUMED). 정차·상차 12분도 장량동 기준선에서 나온 가정이다.
- 엔진이 동당 세대 수를 하나의 평균으로 받으므로 블록 안 건물 간 차이는 평균으로 뭉개진다.
- 결과는 실제 블록 배치에 기반한 가정적 수거 운영 비교다. 실측 민원과 비교한 모델 타당성 검증은 하지 않았다.
