# 브로커가 "없다" 대신 "이렇게 고치면 된다" 고 답하게 한 기록

2026-09-29 · 시작 커밋 `cef337f` → 끝 커밋 `b63cacb` (`feature/simulator-mcp`) · 전체 테스트 593개 중 590개 통과(스킵 3) · 포트 8089(브로커) · 8090(시뮬레이터)

같은 날 [`multi-collection-2026-09-29`](../multi-collection-2026-09-29/REPORT.md) 뒤에 이어진 작업이다.

## 무엇을 바꾸려 했나

명세 그림의 3·4단계 — LLM 이 요청에서 목적과 조건을 뽑아 브로커에 "이런 시뮬레이션을 하는
시뮬레이터 MCP 가 있나" 묻고, 브로커가 가진 목록에서 가장 가까운 것을 찾아 답한다. 바라는 동작은
둘이었다.

- **있으면** 어느 시뮬레이터 MCP 인지 알려 준다.
- **없으면** 없다고 끝내지 말고, **사용자 요청이 어떻게 고쳐지면 그 시뮬레이터를 쓸 수 있는지**
  알려 준다.

바꾸기 전 브로커는 도메인이 맞는 후보를 점수순으로 내고 어긋난 점(`mismatches`)을 나열할 뿐이었다.
도메인이 다르면 후보에서 빼고 "등록돼 있지 않습니다" 한 줄로 끝났다. 어떻게 고치면 되는지는 어디에도
없었다. 목적(`objective`)은 받기만 하고 매칭에 쓰지 않았다 — 그림 4단계의 매칭 근거에는
"수거 시각 비교 가능" 이 있다.

## 바꾼 것 → `e86dc27`

`find_simulators` 응답에 판정(`verdict`)을 둔다.

| verdict | 뜻 | 함께 주는 것 |
|---|---|---|
| `MATCH` | 요청을 그대로 받는, 부를 수 있는 서버가 있다 | `recommended` — 서버 · `endpoint` · 매칭 근거 |
| `ADJUST_REQUEST` | 그대로 받는 서버가 없다 | `suggestions` 마다 `requestAdjustments` — 축 · 지금 값 · 이렇게 바꾸면 · 왜 안 되는지 · `changesPurpose` |
| `NONE` | 부를 수 있는 서버가 하나도 없다 | 사유 |

**정한 것**

- **제안은 카드에 적힌 것에서만 만든다** — 분석 단위, 미지원 항목의 사유와 대안, 답할 수 있는 질문.
  브로커가 지어내면 LLM 이 없는 능력을 사용자에게 약속한다.
- **도메인이 다른 서버도 제안하되 `changesPurpose: true` 로 밝힌다.** 그때는 요청을 고치는 게 아니라
  다른 질문을 하게 된다. 숨기면 사용자는 같은 질문의 답을 받는 줄 안다.
- **지어낸 후보는 맞아도 추천하지 않는다.** 목록에는 `fictional: true` 로 남긴다 —
  `example.invalid` 로 LLM 을 보내면 부를 수 없는 서버를 부른다.
- **목적을 매칭 축에 넣었다.** 카드 네 벌에 `applicability.objectiveMatchKeys`(키 · 한국어 라벨 ·
  매칭 키)를 더했다(추가만). 장량동 카드에는 전날 지원한 하루 수거 횟수(`collection-count`)를 답할 수
  있는 질문에 넣었다.
- **공간 규모도 미지원 선언을 먼저 본다.** 환경 조건이 이미 그렇게 하던 이유와 같다 — 느슨한 별칭에
  걸려 못 하는 일로 점수를 받지 않게.
- 도메인이 다르면 "답할 수 있는 질문" 목록을 도메인 조정에만 싣는다. 목적 조정에도 실으면 같은
  목록이 두 번 나온다(실서버에서 보고 고쳤다).

| 2 | 한 동네에서 수거 비용이 가장 적게 드는 수거 시각을 알고 싶어 | `ADJUST_REQUEST` | 목적 | 민원 · 가동률 · 완료 시각 · 최대 적재로 |

| 5 | 원룸촌 골목 진입이 가능한 수거차 크기를 알고 싶어 | `ADJUST_REQUEST` | 목적 | 목적을 바꾸면 된다(카드에 대안 없음) |

| 7 | 시뮬레이션 민원 수가 실제 민원 기록과 맞는지 검증해줘 | `ADJUST_REQUEST` | 목적 | 설정 간 비교로만 사용 |

| 9 | 우리 동네 상수도 누수 지점을 찾고 싶어 | `ADJUST_REQUEST` | 도메인 | 도메인이 맞는 것은 지어낸 후보(`water-leak-sim`)뿐이라 추천하지 않고, 쓰레기수거 서버를 목적이 바뀐다는 표시와 함께 제안 |

**주의** — 판정은 LLM 이 요청에서 **뽑은 말**에 달려 있다. 매칭은 카드의 매칭 키가 그 말에 들어
있는지를 본다. 예를 들어 4번에서 LLM 이 "차량별 차종" 대신 "혼합 차량" 이라고 뽑으면 걸리지 않을 수
있다. 채팅으로 시험할 때는 브로커 터미널의 `[3 조회]` 줄에서 LLM 이 실제로 무엇을 보냈는지 함께 본다.

**`NONE` 을 보려면** 부를 수 있는 서버가 하나도 없어야 한다. 시뮬레이터를 띄우지 않은 채 브로커만
새로 띄우고 아무 요청이나 보내면 된다 — 브로커에는 지어낸 후보 둘뿐이다.

### 못 하는데 `MATCH` 로 나오는 것 — 한계

[`2-cannot-messages/10-*`, `11-*`](2-cannot-messages/)

| 입력 | verdict | 왜 |
|---|---|---|
| 부산 해운대구 한 동네에서 … | **`MATCH`** | 카드의 "다른 지역" 미지원이 매칭 키 `region:other` 뿐이다. 자연어에 이 말이 없어 걸리지 않고, "한 동네" 가 분석 단위에 걸린다 |
| 건물 30동짜리 한 동네에서 … | **`MATCH`** | "건물 27동 이상" 미지원이 `scale:buildings>26` 뿐이다. 같은 이유 |

둘 다 카드 쪽 문제다 — 사람 말로 된 매칭 키가 없다. 지역은 보정 지역(`region`)과 대조하는 규칙이,
건물 수는 숫자를 읽는 규칙이 필요하다. 이번에는 고치지 않았다.

## 차례대로 넣어 보기 — 6번이 샜다

[`4-sequential-run/`](4-sequential-run/) · 위 표의 아홉 개를 채팅 세션의 LLM 처럼 하나씩 처리했다 —
메시지에서 목적과 조건을 뽑고(2단계), 브로커에 조회하고(3단계), 브로커의 답(4단계)을 사용자에게
전한다. 판정이 `ADJUST_REQUEST` 면 요청을 고칠지는 사용자가 정할 일이므로 거기서 멈춘다.

이번에는 **메시지의 표현을 살려** 뽑았다. 표를 만들 때 쓴 조회와 몇 군데 말이 다르다.

| # | 표를 만들 때 뽑은 목적 | 이번에 뽑은 목적 | 판정 |
|---|---|---|---|
| 1~5, 7~9 | (같거나 비슷함) | | 전부 `ADJUST_REQUEST` — 표와 같다 |
| **6** | 현재 운영 대비 민원 감소 | **지금 운영 방식 대비 민원 감소** | **`MATCH`** — 샜다 |

6번의 근거는 도메인 · 한 동네 · **목적 → 민원 수** 였다. 카드의 "현재 운영과의 비교" 미지원 키가
`현재 운영` · `지금보다` · `기존 방식` · `현행` 뿐이라 "지금 운영 방식" 에 걸리지 않았고, "민원" 만 보고
추천했다. 수정 전 응답은 재시험 때 같은 파일을 덮어써서 JSON 으로는 남지 않았고,
[`call-log.txt`](4-sequential-run/call-log.txt) 의 16:10:31 줄에 남아 있다.

```
16:10:31 [3 조회] domain=쓰레기수거 · scale=한 동네 · env=null · objective=지금 운영 방식 대비 민원 감소
16:10:31 [4 매칭] MATCH → jangnyang-waste-sim (http://localhost:8090/mcp) · 근거 3
```

**고친 것 → `b63cacb`** — 미지원 키에 `지금 운영` · `지금 방식` · `현재 방식` 을 더했다. `운영 방식` ·
`운영 대비` 처럼 넓은 키는 넣지 않았다 — "격일 운영 방식과 매일 운영 방식 비교" 같은 정당한 설정 비교까지
막는다. 두 경우를 시험으로 고정했고, 키 없이 돌리면 첫 시험이 채팅에서와 똑같이 실패하는 것을 확인했다.
시뮬레이터를 다시 띄워 새 카드를 재등록시킨 뒤 같은 입력은 `ADJUST_REQUEST`, 대안 "설정 간 비교" 로
나왔다([`06.json`](4-sequential-run/06.json) 은 이 재시험의 것이다).

**이 사례가 말하는 것** — 판정은 LLM 이 **뽑은 말**과 카드 키의 부분 문자열 대조로 난다. 같은 뜻이라도
다른 말로 뽑히면 샌다. 키를 더해 이번 경우는 막았지만 모든 표현을 막을 수는 없다. 샐 때 알아차리는
자리는 브로커 터미널의 `[3 조회]` 줄이다 — LLM 이 실제로 무엇을 보냈는지 거기서만 보인다.

## 같은 요청을 끝까지 — 시각이 나쁜 2회

[`3-frequency-with-bad-times/`](3-frequency-with-bad-times/) · "1대로 하루에 몇 번" 을 새 브로커로 다시
돌렸다. 브로커는 `MATCH`, 근거에 **목적 → 하루 수거 횟수, 민원 수** 가 나왔다. 전날 보고서가 한계로
남긴 "배출 직후 시각의 2회" 를 한 줄 더했다.

| 하루 수거 | 시각 | 평균 민원 (30일 누적) | 가동률 |
|---|---|---|---|
| 1회 | 11 | 26.9 (±4.8) | 59.3% |
| 2회 | 11 · 23 | 0.0 | 30.0% |
| **2회** | **08 · 14 (배출 직후)** | **0.0** | 29.8% |
| 3회 | 03 · 11 · 19 | 0.0 | 20.0% |
| 4회 | 03 · 11 · 17 · 23 | 0.0 | 15.0% |

**2회면 시각이 나빠도 0 이다** — 30개 시드 전부. 하루 1회일 때는 시각 하나로 27~60건이 움직였는데,
두 번 비우면 어느 시각이든 지점당 쌓이는 양이 임계 24kg 에 닿지 않는다. 전날의 "고른 시각에 달려
있다" 는 한계는 이 두 조합에서는 해당하지 않았다.

## 로그 — 3·4단계를 서버에서 보기

LLM 쪽 화면에는 모델이 보낸 것과 받은 것만 보인다. 두 서버가 도구 호출마다 명세 그림의 단계와 결과를
한 줄씩 남기게 했다(로거 `mcp.calls`) — [`0-call-log.txt`](0-call-log.txt).

```
[3 조회] domain=쓰레기수거 · scale=장량동 전체 · env=null · objective=비용이 적은 수거 시각
[4 매칭] ADJUST_REQUEST → jangnyang-waste-sim 쓰려면 고칠 것: [spatialScale='장량동 전체', objective='비용이 적은 수거 시각']
[3 조회] domain=쓰레기수거 · scale=한 동네 · env=[교통량] · objective=1대로 하루에 몇 번 …
[4 매칭] MATCH → jangnyang-waste-sim (http://localhost:8090/mcp) · 근거 4
[5 템플릿] get_templates → 15개
[9·10 시나리오] build_scenario → scn-23986b85 · 2벌 · UNCONFIRMED · 미승인 1
```

`[3 조회]` 가 서버가 실제로 받은 요청 프로필이다 — LLM 이 사용자 말에서 무엇을 뽑았는지 여기서만
확인할 수 있다. 12단계(사람의 확인)도 같은 로거로 한 줄 남는다. 두 서버 모두 줄 앞에 8자리 요청 id 를
붙인다.

### 로그가 드러낸 것 — 호출마다 2초

첫 실행에서 호출 사이가 정확히 2초씩 벌어져 있었다(15:47:01 → 03 → 05 …). 두 서버는 `127.0.0.1` 에만
바인딩하는데 이 PC 에서 `localhost` 는 `::1` 로 먼저 풀려, IPv6 시도가 실패한 뒤에야 IPv4 로 붙었다.

| 클라이언트 | `localhost` | `127.0.0.1` |
|---|---|---|
| Python | 2.04초 | 0.00초 |
| curl | 0.21초 | 0.005초 |

`.mcp.json` 과 시뮬레이터의 `broker.url` 을 `127.0.0.1` 로 바꿨다. 로그의 16:04 구간(`127.0.0.1` 로 보낸
아홉 건)은 34ms 안에 다 끝났다.

- 지역 · 건물 수 제약을 자연어에서 못 알아본다(위 한계 표).
- 같은 뜻을 다른 말로 뽑으면 미지원 선언을 비켜 간다(6번). 키 추가로 한 경우를 막았을 뿐이다.
- 카드의 대안이 `metric:complaints` 같은 기계용 id 로 나간다. LLM 은 읽지만 사용자에게 그대로 전하면
  어색하다 — 대안에도 한국어 라벨이 있으면 좋다.
- "골목 진입" 처럼 카드에 대안이 없는 미지원은 "목적을 바꾸면 된다" 만 나온다. 무엇으로 바꿀지는 카드가
  말하지 않으므로 브로커도 말하지 않는다.
- 카드의 `endpoint` 와 확인 화면 주소는 아직 `localhost` 다. 브라우저는 IPv6 실패를 빨리 넘기므로
  확인 화면에는 영향이 작지만, `endpoint` 를 그대로 부르는 클라이언트는 같은 지연을 겪는다.

## 재현 방법

```bash
./mvnw.cmd -q -pl broker -am spring-boot:run
./mvnw.cmd -q -pl simulator -am spring-boot:run
```

`1-` · `2-` 와 `3-…/03-*.json` 은 `http://127.0.0.1:8089/mcp` 에, 나머지는 `http://127.0.0.1:8090/mcp` 에
UTF-8 로 보낸다. 12단계는 `http://localhost:8090/` 에서 사람이 누른다. 채팅으로 시험하려면 새 Code
세션을 열어 위 입력 메시지를 넣고, 브로커 터미널의 `[3 조회]` · `[4 매칭]` 줄을 함께 본다.
