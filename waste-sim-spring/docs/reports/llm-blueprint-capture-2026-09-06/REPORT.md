# LLM 설계도 경로 실행 기록

2026-09-06 · 로컬 실행 · 기준 커밋 `faf2efd`

자유 문장으로 시뮬레이터를 요청했을 때 LLM이 설계도를 채우고, 부족한 값만 되묻고, 만들 수
없는 요청은 무엇이 필요한지와 함께 거부하는 경로를 **실제 앱에서** 돌린 기록이다.

## 이 기록의 성격 — 먼저 밝힌다

**PNG 화면 캡처가 아니다.** 이 세션의 도구로는 브라우저 스크린샷을 파일로 저장할 수 없어서,
브라우저에 **실제로 렌더링된 마크업을 그대로 옮긴** HTML 두 개를 남겼다. 앱의 스타일시트를
그대로 링크하므로 열면 화면과 같은 모습이 나온다. 시각 스크린샷은 작업 대화에 남아 있다.

이전 v3 기록(`subtask-v3-capture-2026-09-03`)의 PNG와는 형식이 다르다. 텍스트가 정확하고
검색된다는 점은 낫지만, "그때 화면이 이랬다"는 증거로는 PNG가 더 강하다.

## 기준과 실행 환경

- Java 21.0.10 / Spring Boot 3.2.0 / 활성 프로파일 `ollama`
- 로컬 모델 `qwen2.5:7b` (ollama, `localhost:11434`)
- 실행 주소 `http://localhost:8090`
- 문항 세트 **v4** — 34문항 / 6단계 (v3의 33문항 + `zoneAssignmentRule`)
- 테스트 606개 통과 / 0 실패
- 범위: 거부 경로와 정상 경로 **2건의 실제 UI 실행**. 폴백 경로는 단위 테스트로만 확인했다
  (아래 "확인하지 못한 것" 참조).

## 배선 전에 두 결함을 고쳐야 했다

**앱을 처음 띄웠을 때 이 기능은 한 번도 동작하지 않았다.** 결함 둘이 겹쳐서 그 사실조차
보이지 않았다.

**① 해석기가 산문 응답을 JSON으로 파싱하려 했다.** `OpenAiRequestInterpreter`가
`answerPlain`을 썼는데 그것은 산문 답변용 시스템 프롬프트에 JSON 모드를 끈 호출이다. 모델이
문장을 돌려주고 파싱은 매번 실패했다 — 즉 LLM 경로가 켜져 있어도 늘 문항 흐름으로
폴백했다.

**② 폴백 사유가 화면에 나오지 않았다.** 문항 카드(`SUBTASK`)의 `content`를 프론트가 그리지
않는다 — 카드 렌더러는 `question`만 찍는다. ①과 겹쳐서, 해석기가 매번 죽는데도 화면에는
그냥 34문항이 뜨고 아무도 이유를 몰랐다.

둘 다 `faf2efd`에서 고쳤다. **이 기록을 만들지 않았다면 두 결함은 드러나지 않았을 것이다** —
단위 테스트는 스텁을 쓰므로 ①을 볼 수 없고, ②는 전송된 메시지를 단언하므로 화면에 나오는지를
보지 못했다.

## 1. 범위 밖 요청 거부

입력: **"부산 시뮬레이터 만들어 줘"**

[`01-refusal.html`](01-refusal.html)

화면에 나온 것:

```
이 시뮬레이터는 포항시 북구 장량동만 다룹니다.

필요한 것:
· 교통 구역 정의 — 사람이 채워야 함: 장량동 A~D는 교통량 CSV 링크 매핑과 랜드마크로
  정했습니다. 대상 지역에 그 자료가 없으면 사람이 구역을 정해야 합니다.
· 주민 배출 모델 — 사람이 채워야 함: 0.9kg/인·일과 직업별 외출·귀가 시각은 원룸촌
  논문 모델입니다. 주거 형태가 다르면 맞지 않습니다.
· 도로 자유주행시간 — 자동 수집 가능: OSRM — 구역이 정해지면 자동 수집
· 시간대 혼잡 — 자동 수집 가능: TMAP — 프로파일 1개당 288회 호출
· 수거 일정·미수거일 — 자동 수집 가능: 생활쓰레기 배출정보 표준데이터(시군구별, 채움 편차 있음)
· 인구·세대수 — 자동 수집 가능: 주민등록 통계
```

**수집 세션은 시작되지 않았다** — 화면에 문항 카드가 없다. 배선 전에는 "부산"에도 장량동
34문항을 처음부터 물었고, 사용자는 34개를 답한 뒤에야 자기 요청이 애초에 불가능했다는 것을
알게 됐다.

자동 수집 가능한 넷과 사람이 채워야 하는 둘이 갈려 있다. 후자를 감추면 전부 자동으로 될
것처럼 읽힌다 — 그리고 그 넷이 곧 다음 작업(지역 온보딩)의 재료 목록이다.

## 2. 자유 문장에서 값을 읽어 문항을 줄인다

입력: **"장량동 26개 동으로 한 달치 시뮬레이터 만들어 줘"**

[`02-normal.html`](02-normal.html)

화면에 나온 것:

```
시뮬레이터를 구성하겠습니다. 요청과 기본값에서 24개를 채웠습니다.
남은 9개를 여쭤보겠습니다. (기본값 중 19개는 출처를 확인하지 않은 값입니다)
```

**34문항 → 9문항.** 진행률 막대가 72%에서 시작하는 것이 그 비율이다.

괄호 안의 문구가 이 설계의 정직한 부분이다. 채운 24개 중 **19개는 출처를 확인하지 않은
기본값**이고, 그 사실이 결과가 아니라 첫 화면에서부터 드러난다. 논문을 대조해 승격시키는
만큼 이 숫자가 줄어든다.

### 모델이 실제로 낸 추출

같은 지시문을 로컬 `qwen2.5:7b`에 직접 넣어 확인했다 ([`model-extraction.json`](model-extraction.json)):

```json
{"values":[{"field":"numBuildings","value":26,"span":"장량동 26개 동"},
           {"field":"days",        "value":30,"span":"한 달치"}],
 "targetRegion":"장량동","targetDomain":"","requestedConclusion":""}
```

**`"한 달치" → 30`이 통과하는 것이 요점이다.** 값 30은 문장에 없지만 근거가 된 조각
`"한 달치"`는 있다. 정규화는 해석이고 창작이 아니므로 통과시킨다 — 조각 자체가 없는 값만
버린다. 설계가 실제 모델에서 그대로 성립했다.

## 확인하지 못한 것

**폴백 경로는 실제 UI에서 재현하지 않았다.** 해석기를 죽이려면 ollama를 내리거나 앱을 잘못된
설정으로 다시 띄워야 하는데, 둘 다 이 기록을 위해 하기에는 부작용이 크다. 대신 단위
테스트 두 개가 그 동작을 고정한다 —

- `interpreterFailureFallsBackLoudly` — 문항 흐름으로 가고, 그 사유를 말한다
- `theNoticeArrivesAsAMessageTheScreenActuallyRenders` — 그 사유가 `SUBTASK`가 아닌
  메시지로 나간다(카드에 실으면 화면이 그리지 않는다)

두 번째 테스트는 위 결함 ②를 잡기 위해 만든 것이다.

**시나리오를 끝까지 실행하지 않았다.** 남은 9문항을 답하고 미리보기·실행까지 가는 흐름은
v3 기록(`subtask-v3-capture-2026-09-03`)이 이미 담고 있고, 그 부분은 이번 변경으로 달라지지
않았다.

## 알게 된 한계

**LLM 경로는 규칙 기반 판별기를 통과한 문장에서만 돈다.** `SimulatorCreationDetector`가 먼저
"생성 요청인가"를 판정하고, 그것이 참일 때만 조립기가 불린다. 실제로 겪은 예 —

| 입력 | 결과 |
|---|---|
| "장량동 26개 동으로 한 달치 **시뮬레이터 만들어 줘**" | LLM 경로 (24개 채움) |
| "장량동 26개 동으로 한 달 **돌려줘**" | 일반 답변 — 판별기가 생성 요청으로 안 봄 |

설계 단계에서 판별기를 건드리지 않기로 한 결과이고, 그 결정은 의도적이었다(진입 판정을
LLM에 맡기면 어떤 문장이 수집을 시작하는지 테스트로 고정할 수 없다). 다만 **자유 문장의
이점이 생성 동사를 포함한 문장으로 제한된다**는 사실은 설계 문서에 없던 것이다.

## 되돌리는 방법

`wastesim.llm.blueprint.enabled=false` — 해석기를 호출조차 하지 않고 예전 34문항 흐름으로
돌아간다. `disabledPropertyDoesNotCallTheInterpreter`가 그것을 고정한다.

## 남은 것

- `DEFAULT_BASIS_UNVERIFIED` 플래그는 아직 시뮬레이션 결과에 붙지 않는다. 컴포저가
  `unverifiedFields`를 내고 화면이 개수를 말하지만, 실행 결과 카드까지는 연결되지 않았다.
- `UNVERIFIED` 19개를 논문 대조로 줄이는 일.
- `targetDomain`을 거부 게이트가 읽지 않는다(현재 `requestedConclusion`만 본다).
