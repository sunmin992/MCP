# 구현 보완 결과

기준 커밋 0ddc071에서 시작한 로컬 변경. 커밋·푸시는 하지 않았다.

## 반영 내용

| 단계 | 반영한 동작 | 범위와 남은 일 |
|---|---|---|
| P1 | 공통 요구 계약과 JSON Schema, 카드 버전·형식 검사, 시간 단위 환산, 기간·지역·지표·수치 조건별 판정, 필수/선호 구분 | 자연어 해석은 기존 MCP 클라이언트 LLM이 담당한다. 실제 모델 정확도 측정은 별도 |
| P2 | 제공자 지역 카탈로그, 지역 기본값·출처·해시, 지역별 허용 모드 검사, 장량동/합성 블록 구성 | 현재 엔진이 표현하는 블록·균일 거주민 입력 범위다. 다른 실지역의 건물·도로망 수집 및 임의 도로망 생성은 구현하지 않음 |
| P3 | 지역 데이터 Task와 설정 생성 의존성, 비교 조건별 SES 경로·종류·선택 여부·결정값 기록, 기존 평탄화/역검증 유지 | 새 도메인 모델 생성이 아니라 기존 엔진이 지원하는 SES 선택을 추적함 |
| P4 | 브로커 selection 전달, 카드 식별값·요구 일치 검사, 생성 설정의 기간·지역·필수 수치·관측 지표 재검사, 상태/실행 결과에 검증 기록 연결 | selection은 클라이언트가 전달한 기록이며 서명된 인증·승인 토큰이 아님 |
| P5 | 신규 회귀 검사, 실제 브로커/두 제공자 통합 데모, 자연어 추출 정답 세트와 채점기 | 과학적 모델 타당성·실제 LLM 정확도·실지역 예측 성능은 측정하지 않음 |

기존 API를 유지하며 requirements/selection/conditionChecks 등 선택 필드를 추가했다.
조건부 출력은 브로커에서 CONDITIONAL로 표시하고 상세 구성 단계에서 실제 관측 가능 여부를 확인해야 SATISFIED가 된다.
정보 부족은 UNKNOWN, 불충족은 UNSATISFIED이며 선호 조건 실패는 필수 조건을 통과시키거나 실행을 막는 데 사용하지 않는다.
시간 단위가 같다는 사실과 출력 해상도를 지원한다는 사실은 구분한다. 현재 실제 제공자 카드는 출력 해상도를 새로 보장하지 않는다.
해상도가 필수인데 카드에 선언이 없으면 적합으로 확정하지 않는다. 주 단위/시간 단위 명시적 불일치는 고정 카드 회귀 검사로 검증했다.

## 검증

최종 루트 명령: `.\mvnw.cmd -B clean install` (실패 무시 옵션 없음).
공통 모듈 설치 후 독립 세 프로젝트 각각 `.\mvnw.cmd -B clean package`.

스킵은 기존 Python 참조 엔진 부재에 따른 3건이다. 공통 모듈은 자체 테스트가 없으며 브로커/제공자 검사에서 사용한다.
로그와 test-summary.json을 같은 폴더에 보관한다. 초기 중간 실패 로그보다 root-final-test.log와 각 제공자 최종 로그가 최종 판정 기준이다.

P0-001 수정: 생성기가 템플릿 타입으로 표현하지 못하는 복합 값(wasteTypes)의 조건을 확정 가능한 스칼라 조건처럼 비교하던 부분을 수정했다.
지원하지 않는 타입의 조건은 런타임 조건으로 남겨 필요한 질문을 누락하지 않는 보수적 추출을 유지한다.
기존 JangnyangSourceTest를 완화하지 않았으며 45건 전체가 통과했다. 대신 해당 타입에 대한 정확한 가지치기까지 증명한다고 주장하지 않는다.

추가 검사는 시간 단위/해상도 구분, 누락 능력, 선호 조건, 버전·형식·공통 스키마, 조건부 출력,
카드 변경/요구 변경, 실제 설정 불일치, 합성 지역 입력의 반영과 출처, 지역 데이터 식별값 오류,
미승인 실행 거절, 승인 이후 실행과 매칭 기록 유지, 실패한 수정 후 무효화를 다룬다.
승인→실행 검사는 독립적인 메모리 내 테스트 시나리오에서 확인을 모사했다. 사용자 시나리오를 대신 승인하지 않았다.

## 실제 서버 데모

로컬 브로커(8089), 장량동 제공자(8090), 구 단위 제공자(8091)를 실행해 scripts/demo_requirement_flow.py로 11개 사례를 확인했다.

- 이틀 실행 요청은 장량동을 선택하고 구 단위 제공자는 기간 제약으로 제외.
- 행정동 규모·14일 요청은 구 단위 제공자 선택.
- 기간만 14일로 주면 실제 적합 후보 둘을 CHOOSE로 반환.
- 한 시간 해상도는 선언이 없으므로 MATCH로 확정하지 않음.
- 합성 지역 요구의 선택 기록을 전달하여 실제 시나리오 구성.
- 장량동 데이터로도 별도 시나리오 구성.
- 미승인 실행, 필수 입력 누락, 생성 설정 기간 불일치 차단.
- 실패한 수정 후 이전 시나리오가 STALE이 되는지 확인.

원문 응답은 live-demo.json, 서버 로그는 live-*.log다. 데모는 사용자 승인을 발급하지 않는다.
확인 UI를 변경하지 않았으며 브라우저 시각 검사는 수행하지 않았다.

## 자연어 평가 사용법

extraction-gold.jsonl은 구현 검증용 6개 발화이며 연구 벤치마크가 아니다.
MCP 클라이언트의 모델·프롬프트 버전을 고정하고, 같은 발화를 반복 해석하여 아래 형식으로 저장한다.

```json
{"id":"E1","run":1,"model":"실제 모델 버전","promptVersion":"실제 프롬프트 버전","requirements":{"regionId":"synthetic-block","simulationDuration":{"value":2,"unit":"day"},"requiredOutputs":["meanComplaints"]}}
```

```powershell
python scripts/evaluate_requirement_extraction.py predictions.jsonl
```

채점기는 정확 일치율, 필드 정확도, 임의 추가 필드 비율, 누락 사례와 반복 결과 변동을 출력한다.
예측이 없거나 모델/프롬프트 버전이 섞이면 거절한다. 채점기 자체의 잘못된 예측·빈 입력 처리는 확인했다.
실제 모델 예측은 아직 수집하지 않았으므로 LLM 정확도 수치는 없다.

다음 실증 과제는 두 번째 실지역 데이터 묶음 확보, 지원 모델의 공간 표현 확장 여부 결정,
별도 평가 발화 구축과 실제 LLM 반복 실험이다. 합성 입력 구성 성공을 실지역 일반화 성능으로 해석하지 않는다.
