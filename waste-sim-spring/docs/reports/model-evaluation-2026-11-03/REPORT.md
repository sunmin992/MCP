# 요구 추출·후보 선택 평가와 고정 구성/SES 비교

2026-11-03. 앞서 남은 과제로 정리한 ② LLM 요구 추출·후보 선택 평가와 ③ 고정 구성 대비 SES 비교를 대상으로 했다.
이번에는 제품 실행 코드를 바꾸지 않고 평가 데이터·실행기·집중 실험을 추가했다. 기존 사용자의 실행 완료 시나리오는 그대로 유지했다.

## 결과와 완료 범위

| 평가 | 결과 | 의미 |
|---|---|---|
| 실제 LLM 요구 추출 | **미측정** | 모델 추론 호출이 API 크레딧 부족으로 차단됨 |
| LLM 추출 후 후보 선택 | **미측정** | 성공한 모델 출력이 없어 평가할 수 없음 |
| 정답 구조화 입력 → 실제 브로커 후보 선택 | **24/24 기대 후보 집합과 일치** | 규칙 매칭 구현의 고정 사례 검사이며 LLM 정확도가 아님 |
| 고정 프리셋 구성의 준비 상태 판정 | **9/17 기대 상태와 일치, 잘못된 READY 5건** | 입력 의존성/비활성 가지 검사가 빠졌을 때의 결과 |
| 고정 구성 + 수기 의존성 규칙 | **17/17 일치, 잘못된 READY 0건** | SES와 같은 규칙을 코드로 구현한 대조군 |
| SES 기반 구성 | **17/17 일치, 잘못된 READY 0건** | 현재 입력 존재 조건과 가지 검사가 작동함 |
| 두 방식 모두 유효한 설정의 실행 결과 | **6/6 동일** | 같은 모델·설정·시드에서 출력이 같음 |

따라서 ③의 좁은 범위 구성 검증 비교는 실행했지만, ②의 실제 LLM 실험은 완료하지 못했다.
이 결과로 SES 형식 자체가 동일한 검증 규칙을 가진 다른 구현보다 우수하다고 주장할 수 없다.

## ② 요구 추출 및 후보 선택

### 고정 데이터와 프로토콜

- extraction-gold.jsonl: 폐기물·주차·민원 창구·미지원 버스 도메인의 한국어 발화 24개.
- 포함 조건: 지역명, 블록/행정동 규모, 기간/출력 해상도 구분, 경계값, 결과 지표, 필수/선호 조건, 정보 미제시, 지원하지 않는 요청.
- 각 발화의 기대 구조와 기대 후보 집합을 실행 전에 파일로 고정했다. 이번 작성자가 구성한 소규모 사례이며 독립 전문가 라벨링 자료가 아니다.
- 모델에는 발화와 동일한 추출 명세만 제공하고 정답·기대 후보는 제공하지 않는다. 모델은 도구나 저장소를 읽지 않는다.
- 계획: 발화 24개 × 독립 반복 3회 = 72회, 요청 모델 gpt-4.1-mini, temperature=0.
- 구조화 출력 스키마와 프롬프트 원문·해시, 실제 응답 모델 버전·응답 ID·사용량·지연·원문 출력을 기록하도록 했다.
- 지표: 프로필 정확 일치율, 필드 재현율, 임의 추가 필드 수, 후보 집합 정확 일치율, 부적합 후보 허용 수, 반복 변동.
- 형식 제약과 의미 정확도는 다르다. 출력 형식은 [OpenAI 공식 구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs)에 따라 정의했다.

### 실제 호출 차단

모델 목록 조회는 성공했고 해당 모델 접근 항목도 확인했다. 그러나 첫 발화의 추론 파일럿과 오류 진단 호출 모두 HTTP 429로 실패했다.
오류 코드는 credit_balance_exhausted, 유형은 insufficient_quota였다. 실제 모델 출력은 0건이며 정확도는 **0%가 아니라 측정 불가**다.
파일럿 오류 기록은 pilot/와 pilot-diagnostic/에 있고, [api-blocker.json](api-blocker.json)에 인증 정보 없는 진단을 보관했다.
키·인증 헤더·오류 메시지 원문은 저장하지 않았다. 본 72회 평가를 실패 요청으로 채우지 않았다.
실행기는 첫 호출이 실패하면 후속 평가를 중단하도록 했다.

### 규칙 매칭의 분리 검증

정답으로 지정한 구조화 입력 24개를 실제 find_simulators에 전달했다.
장량동 기반 블록·구 단위 폐기물·주차·민원 창구 제공자 네 곳이 등록되고 응답하는 상태에서 실행했다.
후보 집합은 matches 중 실제 제공자이며 불일치와 모호함이 없는 항목으로 정의했다. 조건부 지원도 포함하되 실행 허가로 해석하지 않는다.
0일 같은 형식상 부적절한 입력의 거절도 사례에 포함한다. 빈 후보 집합이 맞았다는 사실과 실행 성공을 혼동하지 않는다.

24개 모두 사전 지정 후보 집합과 일치했다. 카드 원문은 [capability-snapshot.json](capability-snapshot.json),
브로커 응답과 지표는 [extraction-and-selection-metrics.json](extraction-and-selection-metrics.json)에 있다.
modelEvaluation은 NOT_MEASURED이며 extractionExactRate와 candidateExactRate는 null이다.

### 이어서 실행하기

환경에 설정된 API 계정의 크레딧/사용 한도를 복구한 뒤, 같은 커밋·데이터·카드에서 실행한다.
키를 코드나 채팅에 붙여 넣지 않는다. 네 로컬 제공자와 브로커가 응답하는지 먼저 확인한다.

```powershell
python scripts/run_requirement_model_evaluation.py
python scripts/score_requirement_model_evaluation.py
```

기존 실행 파일을 덮어쓰지 않고 다른 평가를 보존하려면 실행기의 --output을 별도 경로로 지정한다.
현재 채점기는 본 보고서 디렉터리의 predictions.jsonl을 읽는다. 다른 디렉터리 결과는 별도 보존 후 경로를 맞춰 재채점한다.
모델 출력이 없는 상태를 실패한 추출로 세지 않고, 중복/알 수 없는 사례 ID는 거절하는지 채점기 자체도 확인했다.

## ③ 고정 구성과 SES 비교

실행 소스: simulator/src/test/java/com/wastesim/evaluation/ConfigurationComparisonExperiment.java.
기본 *Test 테스트와 별도로 지정 실행하는 실험 클래스다.

```powershell
.\mvnw.cmd -B -pl simulator -am test '-Dtest=ConfigurationComparisonExperiment' '-Dsurefire.failIfNoSpecifiedTests=false'
```

### 세 비교군

1. **FIXED_PRESET:** 같은 기본값에 요청한 값을 덮어쓴 뒤 공통 PesFlattener와 SimulationConfigValidator를 사용한다. 생성 조건에 따른 질문·비활성 가지 검사는 하지 않는다.
2. **FIXED_WITH_MANUAL_RULES:** 같은 구성에 배차·교통·구역 배정·구역 내 이동시간의 의존성을 Java 조건으로 명시한다. SES 식 평가기를 쓰지 않는다.
3. **SES:** 같은 기본값·입력에 실제 SubtaskPlanner와 ScenarioBuilder를 적용한다. 필요한 입력과 가지 선택, 평탄화·역검증을 수행한다.

모델 엔진·기본 설정·범위 검증기는 공유한다. 지역 데이터 효과를 섞지 않도록 장량동 기반 모델로 고정했다.
days=2, seeds=1, 시드=1로 유효 설정을 실제 엔진에서 실행했다.
서버의 사용자 시나리오·확인 토큰은 사용하지 않았다. 메모리 내 실험 입력만 실행했다.
새 편의 도구 create_neighborhood_scenario의 자동 기본값 채우기가 아니라, build_scenario의 명시적 입력 계약을 평가한다.

### 판정 기준과 결과 해석

READY/NEEDS_INPUT/INVALID의 기대 상태를 17개 사례에 미리 지정했다.
복수 차량의 배차 간격 누락, 단일 차량의 불필요한 배차 입력, 비활성 이동 가지 입력,
교통 프로파일 누락, 구역 배정과 구역 내 이동시간의 의존성, 수치 범위 위반을 포함한다.

고정 프리셋은 5개를 잘못 READY로 통과시켰다. 나머지 오분류 3개는 추가 질문이 필요한 상황을 INVALID로 처리한 것이다.
SES와 수기 의존성 규칙은 17개 모두 기대 상태와 일치했다. 두 방식 모두 유효한 6개 설정은 동일 시드의 결과 지표가 전부 같았다.
원문 입력 변경, 선택된 결정, 판정 사유, 실제 결과는 [configuration-comparison.json](configuration-comparison.json)에 있다.

이 실험이 보여주는 것은 **검증 규칙을 누락한 프리셋과 조건부 구성 검증의 차이**다.
동일한 규칙을 가진 대조군도 같은 성능을 냈으므로, SES만의 고유한 정확도 우위는 입증하지 못했다.
유지보수 비용·새 모델 추가 비용·제공자 명세 작성 비용은 이번에 측정하지 않았다.
사례가 작고 의도적으로 제약 경계를 고른 합성 집합이므로 일반적인 사용자 요청에 대한 통계적 성능이나 과학적 모델 타당성을 뜻하지 않는다.

## 검증 및 운영 상태

집중 실험은 실패 0건으로 통과했고, 채점기의 오류/중복 처리와 Python 구문 검사를 확인했다.
새 제품 기능은 변경하지 않았으므로 전체 제품 테스트를 불필요하게 반복하지 않았다.
매칭 실험을 위해 추가 실행한 제공자 3개만 종료했다. 사용자가 실행한 scn-222e8dba는 EXECUTED 상태이며,
기존 브로커와 사용자용 시뮬레이터는 유지했다.
