# 장량동 시뮬레이터 지원 범위 계약

2026-09-23. 근거: [실행 가능한 기능과 범위](../../reports/2026-09-23-장량동-실행가능-기능과-범위.md).

**원칙 — 지금 되는 것만 실행하고, 안 되는 요청은 실행하지 않고 안 된다고 답한다.**
데이터가 없으면 기본값으로 대체하지 않고, 근사로 슬쩍 바꾸지 않고, 거절한다.

분석 단위는 **장량동의 원룸촌 한 블록**이다. 건물 4~26동, 수거 지점 4~26개, 지점 용량 30kg.

---

## 1. 지원 — 그대로 실행한다

| 물을 수 있는 것 | 조절하는 입력 |
|---|---|
| 민원이 가장 적은 수거 시각 | `collectionTimeMinutes` 0~1439분 |
| 하루 여러 번 수거의 효과 | `collectionTimesMinutes` |
| 수거 주기·요일의 효과 | `collectionIntervalDays` 1~365 / `collectionDaysOfWeek` 0~6 |
| 주말·공휴일 처리 | `skipWeekends`, `holidays`, `weekendCollectionTimeMinutes` |
| 차종의 효과 | 5톤 / 2.5톤 / 1톤 (집합 전체 공통) |
| 차량 대수의 효과 | `numTrucks` 1 이상 |
| 배차 간격의 효과 | `dispatchIntervalMinutes` 0~1439 (차량 2대 이상일 때) |
| 교통 반영 여부의 효과 | `trafficEnabled` + 평일 프로파일 |
| 이동시간 계산 방식 | 구간 상수 / 교통구역 근사 |
| 거주민 직업 구성의 효과 | 5종 중 선택, 프리셋 4종 |
| 배출 시각 모델의 효과 | 논문 모델 / 포항시 규정 |
| 분리배출의 효과 | `wasteTypes` (비율 합 1.0) |
| 임대인 점검의 효과 | `landlordEnabled` |
| 계절 변동 | `monthlyWasteFactor` 12개월 |
| 방문 순서의 효과 | `routeSequence` |
| 차량 가동률·용량 | `routeAvailableCapacityKg` (블록 몫 지정) |
| 규모의 효과 | 건물 1~26동, 동당 세대 상한 없음 |

기간 1~365일, 반복 1~100회.

---

## 2. 조건부 — 조건을 채우면 실행한다

조건이 안 채워지면 **묻고, 답을 받기 전에는 실행하지 않는다.**

| 하려는 것 | 필요한 조건 | 없으면 |
|---|---|---|
| 배차 간격 비교 | 실제 운행 차량 2대 이상 = `min(건물 수, 차량 수) ≥ 2` | 이 질문을 **만들지 않는다** |
| 교통 반영 | `trafficProfileId` 지정 | 거부 — 조용히 끄지 않는다 |
| 교통구역 근사, 건물 5동 이상 | 구역 배정 규칙 (덩어리 / 번갈아) | 거부 |
| 구역 배정 = 덩어리 | `intraZoneTravelMinutes` 명시 | 거부 — 0분으로 가정하지 않는다 |
| 용량·가동률 비교 | `routeAvailableCapacityKg` 지정 권장 | 5톤 전체가 분모가 되어 가동률 1.8%로 고정 |
| 분리배출 | 유형별 비율 합 1.0 | 거부 |

구역 배정은 **조사값이 아니라 가정**이다. 결과에 `ZONE_ASSIGNMENT_ASSUMED`로 표시되고,
덩어리·번갈아 두 규칙을 함께 돌려 **범위로 보고**한다. 한쪽 값을 답으로 인용하지 않는다.

## 3. 미지원 — 실행하지 않고 거절한다

| # | 요청 | 사유 코드 | 거절 문안 |
|---|---|---|---|
| 1 | 비용·예산 계산 | `UNSUPPORTED_METRIC` | 비용은 산출하지 않습니다. 연료·인건비·차량 운영비 항이 모델에 없습니다. **민원 수·적재율·차량 가동률·수거 완료 시각**으로 비교하실 수 있습니다 |
| 2 | 실제 도로 기반 이동시간 | `DATA_UNAVAILABLE` | 수거 지점 좌표가 없어 실제 도로 기반 계산을 할 수 없습니다. **교통구역 근사**로 진행할 수 있으며, 같은 구역 안의 방문 순서는 결과에 반영되지 않습니다 |
| 3 | 차량마다 다른 차종 | `UNSUPPORTED_STRUCTURE` | 차종은 투입 차량 전체에 하나만 적용됩니다. 차종별 비교가 필요하면 **차종을 바꿔 여러 번 실행**해 비교하십시오 |
| 4 | 27동 이상 | `OUT_OF_RANGE` | 건물은 최대 26동까지 다룹니다. 더 큰 규모는 이 시뮬레이터의 분석 단위를 벗어납니다 |
| 5 | 장량동 전체 (7만 명 규모) | `OUT_OF_SCOPE` | 이 시뮬레이터는 **원룸촌 한 블록**을 다룹니다. 장량동 전체는 수거 지점이 약 2,700개 필요한데 26개가 상한입니다. 블록 하나로 실행한 뒤 해석하십시오 |
| 6 | 101회 이상 반복 / 366일 이상 | `OUT_OF_RANGE` | 반복은 100회, 기간은 365일까지입니다 |
| 7 | 골목 진입 가능 여부 판정 | `DATA_UNAVAILABLE` | 수거 지점이 등록되어 있지 않아 접근성을 판정할 수 없습니다. **5톤 차량의 진입 가능 여부는 이 실행에서 검증되지 않습니다** |
| 8 | 같은 구역 안 방문 순서 최적화 | `UNSUPPORTED_RESOLUTION` | 교통구역 근사에서는 같은 구역 안의 이동이 모두 같은 평균값이라 순서 차이가 결과에 나타나지 않습니다 |
| 9 | 현재 운영과의 비교 | `NO_BASELINE` | 실제 투입 차량 대수·차종 자료가 없어 현재 운영을 기준선으로 둘 수 없습니다 |
| 10 | 모델이 실제와 맞는지 검증 | `NO_GROUND_TRUTH` | 실제 민원 기록이 없어 결과를 실측과 대조할 수 없습니다. 이 결과는 **설정 간 비교**에 쓰는 것이며 운영 예측이 아닙니다 |
| 11 | 새 모델·엔진 생성 | `OUT_OF_SCOPE` | 기존 시뮬레이터가 지원하는 구성·실험만 다룹니다 |
| 12 | 다른 지역 | `OUT_OF_SCOPE` | 장량동만 다룹니다 |

### 거절 문안의 세 부분

```
[사유]  무엇이 안 되는가
[근거]  왜 안 되는가 — 모델에 없다 / 데이터가 없다 / 범위 밖이다 중 하나
[대안]  대신 무엇을 할 수 있는가 (없으면 "없습니다"라고 적는다)
```

**근거의 세 종류를 구분해서 적는다.** "모델에 없다"(비용)와 "데이터가 없다"(도로 이동시간)는
다르다. 후자는 데이터를 구하면 열리고, 전자는 구현이 필요하다. 사용자가 다음에 무엇을 할지가
달라진다.

## 4. 어느 단계에서 거르는가

빠를수록 좋다. 사용자가 답변을 다 하고 30일 × 30회를 돌린 뒤에 "그건 안 됩니다"를 듣게 하지 않는다.

**요청에 이미 담겨 있는 불가능한 처리는 4단계, 브로커가 서버를 매칭하는 자리에서 알린다.**
7단계까지 미루면 안 된다 — 그때는 이미 서버가 정해진 뒤라, 다른 후보가 그 기능을 지원하는지
따져 볼 기회가 사라진다.

| 단계 | 거르는 것 | 방법 |
|---|---|---|
| **0** 등록 | 미지원 12개 전부 | 능력 카드에 **매칭 키와 함께** 등록 |
| **4** 브로커 매칭 | **요청에 담긴** 불가능한 처리 전부 | 요청 프로필 × 능력 카드 대조 → `요청 중 미지원` 반환 |
| **7** 재요청 | 요청엔 없었지만 진행하다 걸리는 것 (7·9·10) | 질문과 함께 고지 |
| **8** 답변 검증 | 답변으로 들어온 범위 밖 값 (3·4·6) | 재질문, 기본값으로 대체하지 않는다 |
| **10** PES 검증 | 2·8 + 조건부 전부 | 검증 실패로 반환, 실행하지 않음 |
| **15** 결과 전달 | 7·9·10 | 한계로 재고지 |

### 4-1. 브로커가 미지원을 판정하려면

판정은 **요청 프로필(2단계) × 능력 카드(0단계)** 의 대조다. 양쪽에 대조할 수 있는 형태가 있어야 한다.

**0단계 능력 카드** — 미지원 항목마다 매칭 키를 단다.

```
미지원: 비용 산출
  코드    UNSUPPORTED_METRIC
  매칭 키  metric:cost, metric:budget, 비용, 예산, 저렴, 경제적
  대안    metric:complaints, metric:utilization, metric:completionTime
  근거    모델에 연료·인건비·운영비 항이 없음

미지원: 실제 도로 기반 이동시간
  코드    DATA_UNAVAILABLE
  매칭 키  feature:realRoadTravel, 실제 도로, 실도로, 실측 이동시간
  대안    feature:zoneProxyTravel (교통구역 근사)
  근거    수거 지점 좌표 미확보

미지원: 행정동 전체 규모
  코드    OUT_OF_SCOPE
  매칭 키  scale:district, 동 전체, 장량동 전체, 만 명
  대안    scale:block (원룸촌 블록, 건물 1~26동)
  근거    수거 지점 26개 상한
```

**2단계 요청 프로필** — 목적·요구 지표·요구 기능을 구조화해서 담는다.

```
목적       무엇을 결정하려는가
요구 지표   무엇을 기준으로 좋다고 볼 것인가   ← 비용이 여기 들어온다
요구 기능   어떤 계산을 원하는가              ← 실제 도로가 여기 들어온다
공간 규모   어느 크기를 대상으로 하는가        ← 동 전체가 여기 들어온다
```

### 4-2. 4단계 응답에 담기는 것

브로커는 후보와 함께 **요청 중 미지원 목록**을 돌려준다.

```
후보        장량동 시뮬레이터 MCP
매칭 근거    도메인 일치 / 원룸촌 블록 규모 지원 / 교통 반영 지원 / 수거 시각 비교 가능

요청 중 미지원
  [1] 비용 최소화
      사유  이 시뮬레이터는 비용을 산출하지 않습니다
      근거  모델에 연료·인건비·차량 운영비 항이 없습니다
      대안  민원 수 · 차량 가동률 · 수거 완료 시각으로 비교할 수 있습니다
      다른 후보  없음 — 등록된 서버 중 비용을 산출하는 곳이 없습니다

  [2] 실제 도로 기반 이동시간
      사유  수거 지점 좌표가 없어 계산할 수 없습니다
      근거  데이터 미확보 (구현은 되어 있음)
      대안  교통구역 근사 — 같은 구역 안 방문 순서는 반영되지 않습니다
      다른 후보  없음

이 서버의 일반 제한  골목 접근 판정 불가 · 운영 기준선 없음 · 실측 대조 불가
```

**`다른 후보` 칸이 중요하다.** 어느 서버도 지원하지 않는지, 아니면 다른 서버는 되는지에 따라
사용자의 선택이 달라진다. 후보가 하나뿐이면 "등록된 서버 중 없음"이라고 적는다.

### 4-3. 그다음 LLM이 하는 일

미지원이 걸린 자리에 따라 나뉜다.

| 걸린 자리 | LLM의 행동 |
|---|---|
| **목적 자체**가 미지원 (예: "가장 적은 비용으로") | **5단계로 가기 전에** 사용자에게 알리고, 대안 지표로 진행할지 확인받는다. 동의 없이 지표를 바꿔 진행하지 않는다 |
| 부가 조건이 미지원 (예: "실제 도로로") | 7단계 질문 맨 앞에 고지를 붙이고, 대안으로 진행할지 함께 묻는다 |
| 요청에 없던 제한 (골목 판정 등) | 7단계에 고지, 15단계 한계에 재기록 |

목적이 통째로 미지원인데 임의로 다른 지표로 바꿔 실행하면, 결과가 맞아도 **요청 충족 실패**로
센다. 사용자가 물은 것과 답한 것이 다르기 때문이다.

## 5. 절대 하지 않는 것

| 금지 | 왜 |
|---|---|
| 데이터가 없을 때 기본값으로 대체하고 실행 | 어떤 자료로 계산한 값인지 알 수 없게 된다 |
| 실제 도로 모드를 조용히 상수 모드로 낮춤 | 두 모드의 결과가 구별되지 않는다 |
| 교통 프로파일이 없을 때 교통을 조용히 끔 | 설정 오류가 정상 동작처럼 보인다 |
| 구역 내 이동시간을 0분으로 가정 | "이동에 시간이 들지 않는다"는 가정이 숨는다 |
| 사용자 미승인 기본값으로 실행 | 임의 가정이 결과에 섞인다 |
| 잘못된 선택지를 가까운 값으로 보정 | 요청한 것과 다른 실험이 돌아간다 |

마지막 항목이 특히 중요하다. `TruckType.fromName`은 알 수 없는 값에 **예외를 던진다.**
`travelTimeMode`도 마찬가지다. 이 동작을 바꾸지 않는다.

## 6. 결과에 항상 붙이는 것

지원 범위 안에서 실행했더라도 다음을 결과에 싣는다. 엔진이 이미 내보내는 필드다.

```
좌표 품질        구역 근사로 계산했음을 표시
데이터 품질 경고   구역 배정 가정 · 구역 내 이동시간 가정 등
적용된 가정       사용자가 승인하지 않은 기본값
질량 보존 오차     배출 − 수거 − 잔여 = 0 인지
시드·반복         재현 정보
```

그리고 사용자 응답의 **전제**와 **한계**에 최소한 다음을 적는다.

- 거주민 구성·배출 시각·1인 배출량은 **논문값이며 장량동 실측이 아니다**
- 지점 정차시간이 0분이면 **차량 가동률과 수거 완료 시각은 참고치**다
- 이동시간이 교통구역 근사면 **같은 구역 안 방문 순서가 반영되지 않는다**
- 이 결과는 **설정 간 비교**이며 운영 예측이 아니다
