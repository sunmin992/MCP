# 서브태스크 판정 기록 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 시뮬레이터가 `planId` 로 요청의 단계를 세고, 단계마다 서브태스크 상태 · 이유 · 채움 근거 · 최소 필요 단계를 응답 · 로그 · 조회 도구 · JSONL 파일에 남긴다. FILLED 는 형식 검사(그리고 발화가 있으면 근거 검사)를 통과해야 한다.

**Architecture:**
- `SubtaskPlanner` 가 형식 · 근거 기준과 이유를 인스턴스에 싣는다.
- 순수 함수 `MinRounds` 가 최소 필요 단계를 계산한다.
- `@Component PlanRounds` 가 planId 별 단계와 사건을 메모리(LRU 1000)에 두고, `PlanHistoryWriter` 가 사건을 JSONL 로 덧붙인다.
- 도구들(`plan_subtasks`, `validate_answers`, `build_scenario`, `run_scenario_by_token`)과 확인 컨트롤러가 사건을 보낸다. `get_plan_history` 가 메모리 기록을 낸다.

**Tech Stack:** Java 21, Spring Boot, Jackson, JUnit 5, Maven(`./mvnw`)

**Spec:** `docs/superpowers/specs/2026-11-02-서브태스크-판정-기록-design.md` (§6-6 이 경계 결정의 정본)

## Global Constraints

- planId 없이 부르는 기존 흐름은 그대로 동작한다(새 planId 를 발급할 뿐).
- 단계 상한을 두지 않는다. 완료 기준은 `SubtaskPlan.complete()` 정의 그대로다.
- 1단계 = 직전 단계보다 원래 답변 맵 · 출처 맵 · 실험 변수(키 · 값 목록) 중 하나라도 다른 호출이다. `evidence` · `userUtterances` 만 다르면 `recheck` 다.
- planId 형식은 `"plan-"` + UUID 앞 12자다. 메모리 보관은 최근 1000건 LRU 다.
- 파일은 설정값 `plan.history.dir`(기본 `logs/plan-history`) 아래 `plan-history-YYYY-MM-DD.jsonl` 이다. UTF-8, LF, 한 줄 = 한 사건이다. 쓰기 실패는 `log.warn` 만 남기고 도구 응답에 영향을 주지 않는다.
- 사건 공통 칸은 `ts`, `planId`, `matchId`, `serverId`, `sesId`, `sesVersion`, `event`, `round` 이다. `event` 는 `round` / `recheck` / `validate` / `build` / `confirm` / `run` 중 하나다.
- 인스턴스 새 칸은 `reason`(`{code, message}` 또는 null)과 `evidence`(`"VERIFIED"` / `"UNVERIFIED"` / `"NOT_CHECKED"` / null) 이다. `evidence` 는 FILLED 일 때만 값이 있다.
- 근거 검사 실패 코드는 `"NO_EVIDENCE"` 다. 형식 실패 코드는 `AnswerNormalizer` 의 코드(`OUT_OF_RANGE`, `OUT_OF_CLOSURE`, `NOT_A_NUMBER`, `EMPTY_ANSWER`, `DUPLICATE_VALUE`)를 그대로 쓴다.
- `build_scenario` 의 근거 검사 즉시 거절(`ToolFailure` "근거 검사(GUARD)")은 그대로 유지한다. `ScenarioBuilder` 는 근거 없이 planner 를 부른다.
- 커밋 메시지는 한국어 평서문이고, 저장소 형식을 따르며, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` 를 붙인다.
- template-generator 의 기존 실패 1건(`JangnyangSourceTest.뽑은_생성_조건은_물어야_할_때를_빠뜨리지_않는다`)은 고치지 않는다.

## Review Focus

1. **잘못된 값이 생성 조건을 움직이는 경우:** `truckCount="세 대"`(NOT_A_NUMBER)로 배차 간격이 ACTIVE 가 되면 안 된다. 그 결정은 DEFERRED 여야 한다. → Task 1 `형식에서_떨어진_값은_조건_판정에_쓰지_않는다`
2. **같은 답변을 다른 순서로 보낸 호출:** 맵 비교는 순서와 무관해야 한다. 순서가 다르다고 단계가 오르면 안 된다. → Task 4 `키_순서가_달라도_같은_단계다`
3. **비교 변수 값 중 하나만 범위 밖:** 변수 인스턴스는 UNFILLED 이고, `onlyFor` 에 그 값이 실려야 한다. → Task 1 `비교_값_하나가_범위_밖이면_변수는_UNFILLED`
4. **파일 디렉터리를 만들 수 없음:** `plan_subtasks` 는 정상 응답해야 한다. → Task 5 `쓰기_실패해도_응답은_나간다`
5. **동시 호출:** 두 스레드가 같은 planId 로 동시에 부르면 단계 번호가 중복되거나 건너뛰면 안 된다. → Task 4 `같은_planId_동시_호출에도_단계가_한칸씩_오른다`
