# SES 원본화 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 장량동 시뮬레이터에 SES 트리 원본(`jangnyang-ses.json`)을 두고, 템플릿 JSON 과 능력 카드 `sesDigest` 를 그것에서 만들어 내며, `get_ses` 로 제공하고, PES 가 가지친 쪽 값을 싣지 않았는지 검사한다. template-generator 는 소스에서 SES 초안을 결정적으로 뽑는다.

**Architecture:**
- 순수 Java 패키지 `com.wastesim.ses` 가 원본 파일을 읽어 `SesTree` 로 만들고, `SesDerivation` 이 템플릿 · digest JSON 을 파생한다.
- 파생물은 커밋하고, 어긋남 테스트(`SesDerivationTest`)가 지킨다. `-Dses.regenerate=true` 로 돌리면 파일을 다시 쓴다.
- 실행 경로(`TemplateCatalog`, `CapabilityCardLoader`, `BrokerRegistrar`)는 바꾸지 않는다.
- 가지 검증은 `ScenarioBuilder` 안에서, 이미 부르는 `planner.plan(values)` 결과로 한다.

**Tech Stack:** Java 21, Spring Boot, Jackson, JUnit 5, Maven(`./mvnw`), JavaParser(template-generator)

**Spec:** `docs/superpowers/specs/2026-11-02-SES-원본화-design.md`

## Global Constraints

- 사용자가 겪는 동작(질문 순서 · 서브태스크 상태 · 시나리오 · 브로커 판정)은 바뀌지 않는다. 예외는 가지 검증이 새로 막는 경우뿐이다.
- templateId · answerKey · sesPath 값은 지금 그대로 둔다. sesVersion 만 `1.0.0` 에서 `1.1.0` 으로 바뀐다.
- 원본에서 만든 템플릿은 지금 `jangnyang-templates.json` 과 **sesVersion 외에 JSON 트리로 같아야** 한다(필드 순서 무관, 값 · null 유무까지 같음).
- digest 는 지금 카드 14개 decisionPoints 와 `matchKeys` · `field` · `kind` 와 나머지 칸이 같다. 다른 것은 두 가지뿐이다. `occupationMix` · `dischargeTimeMode` 의 `path` 가 템플릿 sesPath 로 바뀌고, 순서가 `decisions` 순서가 된다(`routeAvailableCapacityKg` 가 `capacity` 앞).
- 파일 쓰기는 Jackson pretty-print, UTF-8 이다. 카드는 `sesDigest` 칸만 바꾸고 나머지 키 순서를 유지한다.
- 초안 추출에 LLM 을 쓰지 않는다. 같은 입력이면 바이트까지 같은 출력이다.
- Maven 플러그인을 추가하지 않는다.
- 커밋 메시지는 한국어 평서문이고, 저장소 형식(`feat(ses): …`)을 따르며, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` 를 붙인다.
- template-generator 의 `JangnyangSourceTest.뽑은_생성_조건은_물어야_할_때를_빠뜨리지_않는다` 는 이미 실패하는 테스트다(`binCapacity` · `complaintThreshold`). 고치지 않으며, 실패 수가 1을 넘지 않아야 한다.

## Review Focus

1. **`at` 이 엔티티 키 여러 개와 앞부분이 겹칠 때:** `경로교통` 과 `경로교통/교통구역집합` 이 둘 다 있으면 `경로교통/교통구역집합/프로파일` 은 긴 쪽으로 풀려야 한다. → Task 1 테스트 `가장_긴_엔티티_키로_푼다`
2. **비교 변수 값마다 가지가 갈리는 결정:** 차량 1대/3대를 비교하며 배차 간격(USER)을 실으면, 1대 실행에서만 막혀야 한다. → Task 4 테스트 `비교_값마다_따로_판정한다`
3. **MODEL_DEFAULT 로 실린 가지친 값:** 막지 않고 빼야 한다. 빼지 않으면 평탄화가 그 값을 실행 설정에 넣는다. → Task 4 테스트 `기본값으로_실린_가지친_값은_빼고_통과한다`
4. **원본만 고치고 재생성을 잊은 경우:** 어긋남 테스트가 실패하고, 메시지에 재생성 명령이 있어야 한다. → Task 1 · 2 테스트
5. **카드 재작성이 다른 칸을 건드리는 경우:** `sesDigest` 외의 칸은 JSON 트리로 같아야 한다. → Task 2 테스트 `카드의_다른_칸은_그대로다`

- [ ] **Step 1: 실패하는 테스트를 쓴다** (`SesTreeTest`)

  - `spec_선택지와_allowed_가_다르면_막는다`
  - `결정_순서를_지킨다`: decisions 를 x, y, z 순으로 적으면 `decisions()` 도 그 순서
