# 브로커 — 거주민 조건과 CHOOSE 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 브로커가 요청의 거주민 조건(예: "학생이 많음")으로 시뮬레이터 후보를 거르고, 그대로 맞는 서버가 여럿이면 점수로 고르지 않고 서로 다른 점을 내서 사용자가 고르게 한다.

**Architecture:** `RequestProfile` 에 `population` 칸을 더하고, 능력 카드에 `populationTypes` 를 더한다. `CandidateMatcher` 는 점수를 버리고 거주민 구절을 카드의 `matchKeys` 로 대조한다. `FindSimulatorsTool` 은 그대로 맞는 부를 수 있는 서버가 2개 이상이면 `verdict: CHOOSE` 와 `differences` 를 낸다. 차이는 카드에 이미 있는 칸(`region` · `analysisUnit.label` · 실측 보정)과 거주민 모델에서만 찾는다.

**Tech Stack:** Java 21, Spring Boot 3.2, Jackson `JsonNode`, JUnit 5, Maven 래퍼(`mvnw.cmd`).

**Spec:** `docs/superpowers/specs/2026-10-07-브로커-거주민-조건-후보-선택-design.md`

## Global Constraints

- 브로커는 자연어를 해석하지 않는다. 카드가 적은 `matchKeys` 가 요청 구절 **안에 들어 있는지**만 본다(지금 `anyKeyMatches` 방향 그대로).
- `null` 은 "묻지 않아 모름", 빈 목록은 "그런 조건 없음". `null` 인 조건은 거르는 데 쓰지 않는다.
- 새 의존성을 더하지 않는다.
- 사용자·LLM 에게 나가는 문구와 코드 주석은 한국어, 테스트 메서드 이름도 지금처럼 한국어로 쓴다.
- 가상 후보(`fictional: true`)는 어떤 경우에도 추천(`MATCH`)이나 선택지(`CHOOSE`)에 들어가지 않는다.
- 장량동 카드는 두 군데에 있다 — `simulator/src/main/resources/mcp/jangnyang-capability-card.json`(서빙)과 `docs/superpowers/specs/jangnyang-capability-card.json`(정본, 브로커 테스트가 읽는다). 둘은 같아야 한다(`리소스와_문서의_능력카드가_같다`).
- 모든 명령은 `waste-sim-spring` 폴더에서 PowerShell 로 실행한다.

## Review Focus

1. **한 구절에 직업이 둘** — "학생과 주부가 많음" 처럼 한 구절이 두 유형에 걸려도 통과해야 한다(장량동은 둘 다 다룬다). → Task 3 `한_구절에_직업이_둘이어도_통과한다`
2. **빈 목록** — `population: []` 은 "거주민 조건 없음" 이라 아무 카드도 거주민으로 떨어지지 않아야 한다. → Task 3 `거주민이_빈_목록이면_거르지_않는다`
3. **빈칸 구절** — `["  "]` 같은 구절이 "모든 카드가 못 함" 으로 둔갑하면 안 된다. → Task 1 `거주민_구절의_빈칸은_버린다`
4. **가상 후보가 CHOOSE 에 섞임** — 도메인이 같은 가상 후보가 조건을 다 맞춰도 선택지에 나오면 사용자가 부를 수 없는 서버를 고른다. → Task 5 CHOOSE 테스트에서 후보 목록을 정확히 단언
5. **같은 서버 재등록** — 시뮬레이터는 30초마다 다시 등록한다. 같은 id 가 다시 와도 후보가 둘로 늘면 안 된다. → Task 5 `같은_서버가_다시_등록해도_선택지는_늘지_않는다`

`RequestProfile.java` 의 레코드 선언과 compact 생성자를 바꾸고 5인자 생성자를 더한다. javadoc `@param` 에 한 줄 더한다.

```java
 * @param comparisonAxes        무엇을 바꿔 가며 비교할 것인가. 예: ["수거 시각"]
 * @param population            거주민에 관한 구절. 예: ["학생이 많음", "주부가 많음"]. 해석하지 않고 카드의
 *                              거주민 유형 matchKeys 와 대조만 한다
 */
public record RequestProfile(
        String domain,
        String spatialScale,
        List<String> environmentConditions,
        String objective,
        List<String> comparisonAxes,
        List<String> population) {

    public RequestProfile {
        if (domain == null || domain.isBlank()) {
            throw new IllegalArgumentException(
                    "도메인이 없습니다 — 도메인 없이는 후보를 거를 축이 하나도 없습니다");
        }
        domain = domain.trim();
        spatialScale = blankToNull(spatialScale);
        objective = blankToNull(objective);
        environmentConditions = copyOrNull(environmentConditions);
        comparisonAxes = copyOrNull(comparisonAxes);
        // 빈칸 구절은 버린다 — 남기면 어느 카드와도 맞지 않아 모든 서버가 못 하는 것으로 둔갑한다.
        population = population == null ? null
                : population.stream().filter(s -> s != null && !s.isBlank()).map(String::trim).toList();
    }

    /** 거주민 조건이 없던 시절의 호출부를 그대로 두는 생성자. 거주민은 묻지 않은 것({@code null})이다. */
    public RequestProfile(String domain, String spatialScale, List<String> environmentConditions,
                          String objective, List<String> comparisonAxes) {
        this(domain, spatialScale, environmentConditions, objective, comparisonAxes, null);
    }
```

```java

    /**
     * 그대로 맞는 후보끼리 다른 항목. 브로커는 여기서 고르지 않는다 — 다른 점을 사용자에게 보이고
     * 사용자가 고른다. 값이 모두 같은 항목은 내지 않는다. 다 같으면 빈 목록이다.
     */
    public List<Difference> differences(List<MatchResult> candidates, RequestProfile profile) {
        Map<String, Map<String, String>> items = new LinkedHashMap<>();
        for (MatchResult m : candidates) {
            JsonNode card = registry.byServerId(m.serverId()).orElseThrow();
            put(items, "region", m.serverId(), card.path("region").asText());
            put(items, "unit", m.serverId(), card.path("analysisUnit").path("label").asText());
            put(items, "calibration", m.serverId(), calibration(card));
            if (profile.population() != null) {
                for (String phrase : profile.population()) {
                    JsonNode type = findPopulation(card, phrase);
                    put(items, "population:" + phrase, m.serverId(),
                            type == null ? "" : type.path("model").asText());
                }
            }
        }
        List<Difference> out = new ArrayList<>();
        items.forEach((item, values) -> {
            if (new HashSet<>(values.values()).size() > 1) out.add(new Difference(item, values));
        });
        return out;
    }

    private static void put(Map<String, Map<String, String>> items, String item, String serverId, String value) {
        items.computeIfAbsent(item, k -> new LinkedHashMap<>())
                .put(serverId, value == null || value.isBlank() ? UNWRITTEN : value);
    }

    /** 실측으로 보정한 것만 — 가정값까지 이으면 차이가 보정이 아니라 문구에서 생긴다. */
    private static String calibration(JsonNode card) {
        List<String> out = new ArrayList<>();
        for (JsonNode c : card.path("quality").path("calibration")) {
            if (c.path("measured").asBoolean(false)) {
                out.add(c.path("what").asText() + " (" + c.path("source").asText() + ")");
            }
        }
        return String.join(", ", out);
    }
```
