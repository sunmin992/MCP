# 트럭 용량 모델 보완 계획

## 1. 목적

현재 수거 시뮬레이션은 차종별 정격 적재용량을 실제 엔진에서 강제하고, 경로 배정용량과 초기 적재량을 반영한다. 또한 발생량, 수거량, 잔류량과 트럭 이용률을 결과로 제공한다.

이 문서는 현재 구현의 범위와 한계를 정리하고, 실제 수거 운영에 더 가까운 모델로 확장하기 위한 보완 항목과 구현 순서를 정의한다.

## 2. 현재 구현된 기능

### 2.1 차종별 정격 적재용량

| 차종 | 정격 적재용량 |
|---|---:|
| `LARGE_5TON` | 5,000kg |
| `MEDIUM_2P5T` | 2,500kg |
| `SMALL_1TON` | 1,000kg |

트럭은 한 번의 운행에서 차종의 정격 적재용량을 초과하여 수거할 수 없다.

### 2.2 운행 용량 입력

| 필드 | 의미 | 기본값 및 제약 |
|---|---|---|
| `routeAvailableCapacityKg` | 운행 1회당 해당 경로에 배정된 적재용량 | 미입력 시 차종 정격용량, 정격용량 초과 불가 |
| `initialTruckLoadKg` | 운행 시작 시 이미 적재된 양 | 기본값 0kg, 배정용량 초과 불가 |

실제 신규 수거 가능량은 다음과 같다.

```text
신규 수거 가능량
= min(차종 정격용량, 경로 배정용량) - 초기 적재량
```

예시:

```json
{
  "truckType": "SMALL_1TON",
  "truckCount": 1,
  "routeAvailableCapacityKg": 800,
  "initialTruckLoadKg": 200
}
```

위 조건에서 신규 폐기물 수거 가능량은 600kg이다.

### 2.3 수거 방식

- 트럭은 경로를 따라 수거장을 순서대로 방문한다.
- 같은 운행 안에서는 방문할 때마다 잔여 적재용량이 감소한다.
- 폐기물이 잔여 적재용량보다 많으면 가능한 양만 부분 수거한다.
- 분리배출 유형이 여러 개이면 현재 적재량 비율에 따라 부분 수거한다.
- 다음 트럭 또는 다음 수거 운행에는 새로운 운행 용량이 배정된다.

### 2.4 현재 출력 지표

| 필드 | 의미 |
|---|---|
| `generatedWasteKg` | 시뮬레이션 기간 전체 폐기물 발생량 |
| `collectedWasteKg` | 트럭이 실제로 수거한 양 |
| `residualWasteKg` | 종료 시 수거장에 남은 양 |
| `availableCollectionCapacityKg` | 전체 운행의 신규 수거 가능용량 합계 |
| `truckUtilizationPercent` | 초기 적재량을 포함한 트럭 적재공간 이용률 |
| `collectionCapacityUtilizationPercent` | 신규 수거 가능용량 중 실제 수거에 사용한 비율 |

산식:

```text
트럭 이용률
= (초기 적재량 합계 + 실제 수거량) / 경로 배정용량 합계 × 100

신규 수거용량 이용률
= 실제 수거량 / 신규 수거 가능용량 합계 × 100
```

질량보존의 기본 관계는 다음과 같다.

```text
총 발생량 = 총 수거량 + 종료 시 잔류량
```

## 3. 우선 보완 항목

### 3.1 빈 경로 운행 제외 — 완료

> **구현 완료.** `SimulationEngine`이 방문 노드가 없는 경로는 운행 이벤트를 생성하지 않으며, 배정용량·초기 적재량·완료시간 분모에서도 제외한다. 회귀 시험 `TruckCapacityRefinementTest.emptyRoutesDoNotInflateCapacityDenominator`.

트럭 수가 건물 수보다 많으면 방문할 건물이 없는 트럭이 생길 수 있다. 빈 경로까지 운행으로 집계하면 용량 합계가 증가하여 트럭 이용률이 실제보다 낮아질 수 있다.

권장 처리:

```text
방문 노드가 없는 경로
→ 운행 이벤트 생성 제외
→ 배정용량 합계에서 제외
→ 초기 적재량 합계에서 제외
→ 이용률 분모에서 제외
```

필수 시험:

- 건물 2개, 트럭 4대 조건에서 실제 운행은 2개만 생성되는지 확인
- 빈 경로 추가 전후 실제 수거량이 변하지 않는지 확인
- 이용률 분모에 빈 경로 용량이 포함되지 않는지 확인

### 3.2 초기 적재량 적용 범위 명시

현재 설정은 동일한 `initialTruckLoadKg`를 모든 트럭과 모든 운행에 반복 적용한다. 하루 두 번 운행할 때 오전과 오후 운행 모두 같은 초기 적재량으로 시작하는 셈이다.

다음 중 하나를 명시적으로 선택할 수 있도록 보완해야 한다.

| 정책 | 설명 |
|---|---|
| `EVERY_TRIP` | 모든 운행에 같은 초기 적재량 적용 |
| `FIRST_TRIP_PER_TRUCK` | 트럭별 최초 운행에만 적용 |
| `EXPLICIT_BY_TRIP` | 운행별 초기 적재량을 직접 설정 |

권장 신규 필드:

```json
{
  "initialLoadPolicy": "FIRST_TRIP_PER_TRUCK"
}
```

### 3.3 부분 수거 및 용량 소진 지표 — 완료

> **구현 완료.** 아래 4개 지표가 `SimulationResult`에 출력되며 다중 시드 요약에도 반영된다. 회귀 시험 `TruckCapacityRefinementTest.tightCapacityRecordsPartialUnservedAndUncollectedDemand`.

현재 엔진은 부분 수거를 수행하지만 결과에서 발생 횟수와 미수거 수요를 직접 확인하기 어렵다.

출력 지표:

| 필드 | 의미 |
|---|---|
| `partialPickupCount` | 요청량 중 일부만 수거한 방문 횟수 |
| `unservedPickupCount` | 잔여 용량이 없어 전혀 수거하지 못한 방문 횟수 |
| `capacityExhaustedTripCount` | 적재용량을 모두 사용한 운행 수 |
| `uncollectedDemandKg` | 수거 시점에 용량 부족으로 남긴 폐기물 양(다음 운행에서 재수거 가능하므로 종료 잔류량과 별개) |

이 지표가 있어야 잔류량이 배출 시점 문제인지 트럭 용량 부족 문제인지 구분할 수 있다.

### 3.4 트럭별·운행별 결과 출력 — 완료

> **구현 완료.** `SimulationResult.tripMetrics`(List&lt;TripMetric&gt;)로 운행별 상세를 출력한다. 운행 스케줄은 시드와 무관하게 결정되므로 다중 시드 요약에서는 같은 `tripId`끼리 수거량·이용률을 평균한다. 채팅 응답과 웹 UI에는 트럭별 롤업(운행 수·수거량·부분수거 발생 운행 수)으로 요약해 병목 트럭을 드러낸다. 회귀 시험 `TruckCapacityRefinementTest.tripMetricsCaptureBottleneckTrip`·`emptyRoutesProduceNoTripEntries`.

전체 평균만으로는 병목 트럭이나 문제 경로를 찾기 어렵다. 다음과 같은 운행 상세 결과를 추가하는 것이 바람직하다.

```json
{
  "tripMetrics": [
    {
      "truckId": "T1",
      "tripId": "T1-D0-S0",
      "allocatedCapacityKg": 1200,
      "initialLoadKg": 200,
      "availablePickupCapacityKg": 1000,
      "collectedKg": 900,
      "finalLoadKg": 1100,
      "unusedCapacityKg": 100,
      "utilizationPercent": 91.67,
      "partialPickupCount": 1
    }
  ]
}
```

### 3.5 건물별·폐기물 유형별 잔류량 — 부분 완료

> **부분 완료.** `residualByBuilding`·`residualByWasteType`·`residualByTruck`·`maxResidualBuilding`/`maxResidualBuildingKg`가 결과에 출력되고 다중 시드에서는 키별로 평균한다. 채팅은 최대 잔류 건물을, 웹 UI는 유형별 잔류 + 최대 잔류 건물을 표시한다. 회귀 시험 `TruckCapacityRefinementTest.residualDistributionByBuildingAndType`. **임계 이상 잔류 지속시간**은 연속시간 추적이 필요해 후속 작업으로 남긴다.

전체 잔류량이 같더라도 특정 건물에 집중된 경우 민원과 위생 위험이 더 커질 수 있다.

출력:

- 건물별 최종 잔류량 ✅
- 폐기물 유형별 최종 잔류량 ✅
- 최대 잔류 건물과 잔류량 ✅
- 경로별 미수거량(트럭별) ✅
- 임계 이상 잔류 지속시간 ⏳ (후속)

## 4. 모델 정합성 보완

### 4.1 예측기와 엔진의 운행 달력 통일

현재 예측 적재율은 평균 운행 횟수를 사용하지만 실제 엔진은 날짜별 일정을 적용한다. 다음 조건에서 예측기와 엔진 사이에 차이가 발생할 수 있다.

- 주말 미수거
- 공휴일 미수거
- 격일 수거
- 하루 다회 수거
- 폐기물 유형별 수거 주기
- 연속 미수거 후 누적

개선 방향:

1. 시뮬레이션 기간의 실제 수거일과 슬롯을 계산한다.
2. 운행별 신규 수거 가능량을 합산한다.
3. 같은 기간의 예상 발생량과 비교한다.
4. 전체 평균뿐 아니라 최대 연속 미수거 구간의 적재 위험도 함께 검사한다.

### 4.2 종료 시점 효과 분리

마지막 날 수거 이후 발생한 폐기물은 종료 잔류량에 포함된다. 이는 실제 용량 부족이 아니라 관찰 기간 종료 때문에 남은 양일 수 있다.

권장 방법:

- 마지막 배출 이후 추가 정리 운행을 수행하는 `drainPeriodDays` 지원
- `endOfHorizonResidualKg`를 별도 출력
- 용량 부족 잔류량과 종료 경계 잔류량 분리

### 4.3 반올림과 질량보존

내부 계산값을 각각 반올림하면 표시 결과에서 작은 질량보존 오차가 나타날 수 있다.

권장 처리:

- 내부 계산은 원본 정밀도로 유지
- API 또는 화면 표시 단계에서만 반올림
- 다음 진단값 추가

```text
massBalanceErrorKg
= generatedWasteKg - collectedWasteKg - residualWasteKg
```

> **부분 완료.** `massBalanceErrorKg`가 결과에 출력된다(내부값은 원본 정밀도, 표시 단계에서만 반올림). 유형별 비율 합이 1이면 0에 수렴함을 `TruckCapacityRefinementTest.massBalanceHoldsForSingleWasteType`가 확인한다. 허용 오차 초과 시 자동 오류 표시는 후속 작업으로 남긴다.

## 5. 트럭별 설정 구조

혼합 차종과 차량별 상태를 지원하려면 단일 전역 설정을 트럭 목록 구조로 확장해야 한다.

권장 입력:

```json
{
  "trucks": [
    {
      "truckId": "T1",
      "truckType": "LARGE_5TON",
      "routeAvailableCapacityKg": 4000,
      "initialTruckLoadKg": 500
    },
    {
      "truckId": "T2",
      "truckType": "SMALL_1TON",
      "routeAvailableCapacityKg": 800,
      "initialTruckLoadKg": 0
    }
  ]
}
```

하위 호환 원칙:

- `trucks`가 없으면 기존 `truckType`, `truckCount`, `routeAvailableCapacityKg`, `initialTruckLoadKg`를 사용한다.
- `trucks`가 있으면 전역 트럭 설정과 동시에 사용하지 못하도록 검증한다.
- `truckId`는 중복될 수 없다.
- 각 차량의 배정용량은 해당 차종 정격용량 이하여야 한다.

## 6. 처리장 하역 모델

현재는 다음 운행이 시작될 때 트럭 용량이 즉시 복구된다. 실제 운영에서는 처리장 이동, 진입 대기와 하역이 끝나야 다음 수거가 가능하다.

권장 입력:

| 필드 | 의미 |
|---|---|
| `disposalTravelMinutes` | 마지막 수거장에서 처리장까지 이동시간 |
| `unloadingMinutes` | 트럭 1대의 하역시간 |
| `disposalQueueMinutes` | 평균 처리장 대기시간 |
| `disposalCapacityKgPerHour` | 처리장 시간당 처리용량 |

분석 가능한 결과:

- 처리장 혼잡으로 인한 다음 운행 지연
- 트럭은 충분하지만 하역 능력이 부족한 상황
- 수거 횟수 증가와 처리장 병목의 상충관계
- 마지막 노드 미방문 또는 다음 운행 취소 가능성

## 7. 중량·부피 이중 제약

생활폐기물은 중량 한도보다 적재함 부피가 먼저 부족해질 수 있다. 장기적으로는 중량과 부피를 동시에 제한해야 한다.

권장 입력:

| 필드 | 의미 |
|---|---|
| `truckVolumeCapacityM3` | 트럭 적재함 유효 부피 |
| `wasteDensityKgPerM3` | 폐기물 유형별 밀도 |
| `compactionRatio` | 압축장치에 의한 부피 감소 비율 |

수거 가능량은 중량과 부피 조건을 모두 만족해야 한다.

```text
수거 가능
= 중량 잔여용량 이내 AND 부피 잔여용량 이내
```

## 8. 비용 및 운영 효율 평가

트럭 이용률이 높다고 반드시 좋은 운영은 아니다. 트럭을 항상 가득 채우려 하면 잔류량과 부분 수거가 증가할 수 있다.

함께 평가할 지표:

- 수거량당 운행시간
- 수거량당 이동거리
- kg당 연료비 또는 에너지 소비량
- 트럭 1대당 처리량
- 민원 1건 감소당 추가 비용
- 잔류량 1kg 감소당 추가 비용
- 적재율과 서비스 실패율의 상충관계

권장 종합 비교 항목:

```text
운영안 평가
= 민원 + 잔류량 + 부분 수거 + 운행시간 + 에너지 + 비용
```

단위가 다른 값을 단순 합산하지 말고 각각 별도 출력한 뒤, 사용자가 가중치를 명시한 경우에만 종합점수를 계산한다.

## 9. 예외 및 고장 시나리오

실제 운영 안정성을 검토하려면 정상 상황뿐 아니라 다음 시나리오도 필요하다.

- 트럭 1대 운행 중단
- 특정 운행 취소
- 압축장치 고장으로 유효 부피 감소
- 예상보다 많은 초기 적재량
- 교통 지연으로 마지막 수거장 미방문
- 처리장 운영 중단 또는 대기시간 급증
- 계근 오차와 배출량 예측 오차

결과는 평균뿐 아니라 최악 조건과 복구 시간도 함께 비교한다.

## 11. 완료 판정 기준

보완 작업은 다음 조건을 만족할 때 완료로 본다.

- 빈 경로가 이용률 계산에 포함되지 않는다.
- 모든 운행에 대해 배정용량, 초기 적재량, 수거량과 최종 적재량을 추적할 수 있다.
- 부분 수거와 미수거 사유를 결과에서 구분할 수 있다.
- 건물별·폐기물 유형별 잔류량을 확인할 수 있다.
- 검증기와 엔진이 동일한 운행 달력과 용량 가정을 사용한다.
- 질량보존 오차가 정해진 허용 범위 안에 있다.
- 기존 단일 트럭 입력과 결과의 하위 호환성이 유지된다.
- 정상·용량 부족·다회 운행·빈 경로·연속 미수거 조건에 대한 자동화 테스트가 통과한다.

## 12. 현재 검증 상태

현재 구현은 다음 결정론적 조건을 검증한다.

```text
발생량: 1,800kg
경로 배정용량: 1,200kg
초기 적재량: 200kg
신규 수거 가능량: 1,000kg
실제 수거량: 1,000kg
종료 잔류량: 800kg
트럭 이용률: 100%
신규 수거용량 이용률: 100%
```

질량보존 결과:

```text
1,800kg = 1,000kg + 800kg
```

현재 전체 자동화 테스트 376개가 통과한 상태이며(P1~P4 보완으로 7건 추가), 이후 보완 과정에서도 이 회귀 기준을 유지해야 한다.

추가로 P1(빈 경로 제외)·P2(부분수거·미수거·용량소진 지표)·P3(운행별 상세)·P4(잔류 분포)·§4.3(질량보존 진단)의 결정론적 조건을 `TruckCapacityRefinementTest` 7종이 검증한다.
