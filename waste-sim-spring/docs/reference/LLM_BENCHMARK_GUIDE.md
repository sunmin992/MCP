# 장량동 템플릿 기반 LLM 벤치마크 안내

`llm_benchmark.py`는 로컬 LLM이 최신 장량동 서브태스크 템플릿에 맞춰 사용자 요청을
구조화하고 시나리오 초안을 만들 수 있는지를 측정한다. 실행 요청 분류 오탐률, 일반 답변 품질,
결과 해설의 사실성은 측정하지 않는다.

벤치마크는 `src/main/resources/subtask/jangnyang-simulator-v4.json`을 직접 읽는다. COLLECT
서브태스크의 `answerField`, `answerType`, `allowedRange`, `validationRule`, `retryQuestion`과
전역 `invalidValuePolicy`가 시스템 프롬프트에 포함된다. 케이스 라벨이 템플릿과 모순되면 모델
호출 전에 실패한다.

## 측정 지표

| 지표 | 의미 |
|---|---|
| 완전 통과 | 한 요청에서 아래 조건을 모두 만족한 실행 비율 |
| 응답/시도·호출 오류 | 응답을 받은 횟수와 별도로 집계한 통신 오류 횟수 |
| JSON | JSON 파싱 성공률. 출력 계약 준수와는 별개 |
| 출력 계약 | 필수 키·자료형·중복·추가 키 검사 통과율 |
| 필드 재현 | 명시된 파라미터를 빠뜨리지 않은 비율 |
| 값 정확 | 추출값과 정규화 결과가 기대값과 일치한 비율 |
| span | 근거 조각이 실제 사용자 원문에 존재한 비율 |
| 제약판정 | 타입·범위·열거값에 따른 `valid` 판정 일치율 |
| 재질문 | 제약 위반 필드만 `reaskFields`에 넣은 실행 비율 |
| 시나리오 | 유효한 명시값만 시나리오 초안에 보존한 실행 비율 |
| 무창작 | 값이 없는 요청에서 임의 파라미터를 만들지 않은 비율 |

`완전 통과`를 모델 선택의 기본 지표로 본다. 잘못된 값을 시나리오에 넣거나 재질문 대상을
틀리면 해당 실행은 통과하지 않는다. `무창작`은 실행 의도 오탐률이 아니라 파라미터가 없는
요청에서 값을 지어내지 않는지를 뜻한다.

## 실행

Ollama를 실행한 뒤 실행한다.

```powershell
python llm_benchmark.py
```

한 모델로 빠르게 확인하려면 환경변수를 지정한다.

```powershell
$env:BENCHMARK_MODELS = "qwen2.5:7b"
$env:BENCHMARK_RUNS = "1"
python llm_benchmark.py
```

결과는 `benchmark_report.md`, 실패별 모델 원문은 `benchmark_detail.log`에 저장된다.

## 채점 버전 2 (2026-09-08)

`{}`와 필수 키 누락은 실패다. 명시적인 `values: []`, `reaskFields: []`, `scenario: {}`와
메타데이터 문자열 세 필드를 모두 제공해야 빈 추출 계약이 성립한다. 추가 키, 중복 필드,
문자열로 쓴 `valid`, 잘못된 자료형도 계약 실패다. 계약 실패는 재질문·시나리오·무창작을
포함한 의미 평가를 통과시키지 않는다. 미등록 필드를 values에 넣어도 무창작 통과가 아니다.

호출 오류는 응답 기반 모델 점수의 분모에서 제외하고 별도 표시한다. 응답이 전혀 없으면
성능과 지연은 `-`(미측정)다. JSON 파싱·계약 실패는 응답 기반 분모와 기대 필드 분모에
포함하므로 실패 응답이 많다고 추출 정확도가 높아지지 않는다. 무창작 분모는 실제 응답을
받은 무창작 케이스 수다. 호출 성공률과 모델 점수를 반드시 함께 읽는다.

기존 보고서는 이전 채점 결과이며 자동으로 갱신되지 않는다. 성공 응답 원문이 기존 로그에
없으므로 그 로그만으로 전체 성능을 재계산할 수 없다. 새 수치는 재실행해야 한다.

채점 회귀 검사는 모델 호출 없이 `python -m unittest test_llm_benchmark -v`로 실행한다.
