# 시나리오 준비 상태와 근거 검사

2026-11-03 보완. 장량동·주차·민원창구·구 단위 폐기물 시뮬레이터에 적용한다.

## 완료의 세 단계

`plan_subtasks.complete`는 필요한 입력 결정의 완료이다. 실행 가능이나 사용자 승인을 뜻하지 않는다.

`build_scenario.taskReadiness`는 시뮬레이터 제공자의 `/ses/task-manifest.json`에 등록된 Task를 비교 조건마다 구성하고 다음 조건을 평가한다.
SES 경로로 Task를 추측하지 않는다. 명세에는 Task ID·이름·선행 Task·소속 Subtask·산출물·검증 방법이 있으며
기동 시 템플릿 전체가 빠짐없이 한 Task에 소속되는지 검사한다. 알 수 없는 검증 방법, 순환, 중복 소속,
검증 단계 누락, 최종 시나리오 Task와 연결되지 않은 작업은 거절한다.

1. 각 구성 Task: 필요한 Subtask가 FILLED이고 DEFERRED/UNFILLED가 없어야 한다. NOT_GENERATED는 면제한다.
2. execution-settings Task: 구성 Task들이 완료되고, 시뮬레이터 고유 설정 검증을 통과하며 실행 조건이 하나 이상이어야 한다.
3. settings-roundtrip Task: execution-settings가 완료되고 입력 결정과 실제 실행 설정의 역검증을 통과해야 한다.
4. scenario Task: 앞의 작업과 시나리오 통합 검증(장량동의 가지치기 검증 포함)을 통과해야 한다.

공통 `TaskCompletion`은 선행 Task, 필수 Subtask, 서버 검증 함수를 평가한다. 실패한 Task는 INVALID,
선행 작업이나 입력이 부족한 Task는 BLOCKED, 모두 통과하면 COMPLETE이다. 검증 함수 예외도 실패로 처리한다.
누락된 의존 Task, 중복 ID, 순환은 정의 오류로 거절한다. 모든 Task가 완료돼야 ready가 true이다.
도구는 기존 scenario.valid와 taskReadiness.ready가 모두 참일 때만 저장한다. 사용자 확인 전에는 실행 토큰이 없다.

주차 API 모드의 시설면수는 사용자가 입력하는 단일 값 대신 검증된 ParkingSnapshot으로 충족한다.
스냅샷 자체와 실행 설정에 대한 기존 주차 전용 검증은 그대로 적용한다.

## 큰 시뮬레이터의 확장

현재 제공자 명세는 차량·수요·정책·실험 등의 작업과 설정 검증 단계를 정의한다. 도로망 연결성 검사 같은 도메인은 아직 구현하지 않았다.
새 시뮬레이터는 task-manifest.json에 Task를 등록하고, 서버 검증 함수를 연결해 실제 파일·데이터·산출물을 검사해야 한다.
추가 검증 방법은 TaskManifest.load(owner, registeredValidators)로 서버에서 등록하며
instantiateWithChecks의 함수 목록에 실제 검증 함수를 제공한다. 등록하지 않은 방법이나 함수 누락은 거절한다.
파일 경로나 클라이언트가 보낸 completed=true만으로 통과시키지 않는다. 선행 Task가 실패하면 후속 검증은 실행하지 않는다.
공통 엔진의 회귀 테스트는 경로 입력이 FILLED여도 산출물 검증이 실패하면 Task와 전체 준비가 실패하는지 확인한다.

## 목적–시나리오–결과 연결

`get_templates.taskManifest`로 제공자 작업 명세와 사용 가능한 결과 지표를 조회한다.
`build_scenario`에는 기존 입력에 다음 목적 명세를 추가할 수 있다.

```json
{
  "requestId": "이전 응답에서 받은 요청 ID",
  "variableAnswerKey": "collectionTimeMinutes",
  "variableValues": [360, 1080],
  "observations": ["meanComplaints"],
  "purpose": {
    "mode": "COMPARE",
    "comparisonKey": "collectionTimeMinutes",
    "comparisonValues": [360, 1080],
    "observations": ["meanComplaints"]
  }
}
```

이 예시는 전체 요청이 아니라 목적 관련 필드의 예이다. 기존 values·request·origins 등도 함께 전달한다.
COMPARE는 요청한 변수·값 집합과 실제 실험 조건이 일치하고, 변환된 실행 설정도 두 종류 이상이어야 한다.
RUN은 비교 차이를 요구하지 않으며 관측 지표를 검사한다. 목적 지표가 observations에 포함되고
현재 모든 실행 조건에서 관측 가능해야 한다. 예를 들어 이동을 계산하지 않는 설정에서 운행 소요 시간을 약속하지 않는다.
불일치하면 valid=false이고 저장·승인·실행으로 넘어가지 않는다.
실행 후에도 실제 결과의 지표 경로가 존재하고 null이 아닌지 검사한다. 검사를 통과하면 purposeResultCheck=VERIFIED이다.
이 표시는 필요한 지표가 실제로 반환됐다는 뜻이며, 시뮬레이터 모델의 과학적 타당성을 증명한다는 뜻은 아니다.

기존 호출과의 호환을 위해 purpose는 선택 사항이다. 생략하면 purposeCheck.status=NOT_SPECIFIED이며
자동으로 목적 충족을 확인했다고 주장하지 않는다. 확인 화면에서 원래 요청과 설정을 대조하도록 표시한다.
목적 명세 자체도 클라이언트가 전달하므로 자연어 요청을 완벽히 해석했다는 보장은 없다.
현재 비교 명세는 기존 실험 프레임과 같이 단일 비교 축을 지원한다.

## 입력 변경과 검증 결과 무효화

서버는 검증 시각, 명세 버전, 실제 실행 설정 산출물 수·SHA-256, 제공자 리소스의 SHA-256,
Task별 판정 및 목적 대조 결과를 검증 기록(validation)에 저장한다.
확인 화면과 get_scenario_status에서 이 기록을 읽을 수 있다.

입력·출처·실험 조건·목적·관측 지표·요청 원문이 바뀌면 같은 requestId의 이전 기록을 무효화한다.
실패한 수정 요청도 이전 승인을 유지시키지 않는다. 후속 plan_subtasks/build_scenario에 이전 requestId를 재사용해야
같은 사용자 요청으로 연결된다. requestId가 없으면 build_scenario는 새 ID를 발급한다.
장량동에서는 planId의 단계 변경·만료도 기존 기록을 무효화한다.

확인 전·실행 전·실행 결과 채택 시에 실제 설정과 제공자 데이터의 식별값을 다시 검사한다.
불일치하면 STALE로 표시하고 이전 토큰을 숨기며 재생성·재검증·재승인을 요구한다.
실행 중 요청이 바뀌면 그 실행 결과도 채택하지 않는다. 검증에 실패한 기록은 재사용하지 않는다.
서버가 기동 때 읽은 제공자 리소스가 디스크에서 바뀌면, 메모리 데이터와 파일이 어긋날 수 있으므로
새 시나리오 생성도 거절하고 서버 재시작을 요구한다. 주차 API 스냅샷은 실행 설정 안의 고정 데이터와 함께 식별한다.

목적 명세·입력 데이터가 서로 다른 요청 ID로 전달되면 별도 요청으로 취급한다.
외부 데이터베이스 전체의 변경을 자동 감지하는 기능은 아니며, 새 외부 산출물은 실제 데이터의 식별값과 검증 함수를 연결해야 한다.

## 발화 근거 정책

정책은 서버가 고정한 REQUIRE_CONFIRMATION_FOR_UNVERIFIED이다.

- 발화가 제공되면 기존 근거 검사를 수행한다. 근거와 숫자가 모순되면 차단한다.
- 발화 목록이 생략되면 evidenceStatus=NOT_CHECKED이다. 누락을 검증 성공으로 취급하지 않는다.
- 판정하지 못한 값과 근거 미제공 값은 PES.evidenceChecks에 따로 저장한다. 원래 origins와 혼동하지 않는다.
- 확인 화면은 reviewRequiredValues(기본값 + 근거 미검증 값)를 표시한다. 기존 사람 전용 확인·승인 단계가 이 값들까지 승인한다.
- 미확인 시나리오는 토큰이 없어 실행할 수 없다. 승인은 근거 검증 성공을 뜻하지 않으며 evidenceChecks를 지우지 않는다.
- 클라이언트가 전달한 발화 원문이 실제 대화 기록인지 인증하는 기능은 아니다.

숫자 변환은 공통 NumericEvidence를 사용한다. 횟수·대수에는 시간 배수를 허용하지 않는다.
분 단위 필드는 시간 표현이 있을 때만 시간→분, 일 단위는 주→일,
비율 필드는 퍼센트→비율 변환을 허용한다. 자연어 의미 전체를 검증하는 방법은 아니다.

## 단계 지표

dependencyDepth는 생성 조건의 의존 계층 수이다. 최소 질문 횟수와 다르다.
minRounds는 기존 클라이언트 호환을 위한 폐기 예정 별칭이며 동일한 값을 반환한다.
round는 입력·출처·비교 조건 변경 횟수(INPUT_REVISION_COUNT)이며 실제 사용자 질문 횟수가 아니다.

```powershell

```
