> 미팅(교수님·참석자 논의) + 시뮬레이터 분석 + 현재 코드 상태를 하나로 합친 문서.
> 관련 코드: `src/main/java/com/wastesim/edge/`, 측정: `scripts/edge/`, 설계 상세: `RE_엣지_발열실험_설계.md`

## 0. 한 줄 요약

**"최고 냉각"이 아니라 "적정 비용으로 충분한 냉각"을 찾는 연구**다. 발표 때 반드시 나올
*"왜 이걸 해야 하나?"* 의 답이 곧 결론이다 — 지속가능성(SDGs).

---

## 1. 문제 구조 — "왜 이걸 해야 하나"

발표에서 이 질문이 반드시 나온다. 답을 미리 세팅한다.

```
AI 데이터센터 발열 → 성능 저하(스로틀링) → 냉각 필요
→ 최고 냉각 시스템은 비용 과다 → 지속가능성 하락
→ 냉각 성능을 조금 낮추더라도 비용을 크게 줄이는 방법이 필요
```

**결론 지점**: 비용 대비 성능을 적정 수준에서 유지하는 방법을 찾는다. 공대의 사고방식은
"비싸면 좋다"가 아니라 **"적정 수준으로 내려와도 되면 선택지가 훨씬 넓어진다"**이다.

평가 기준(참석자 2): **"면적을 절반(비용 절반)으로 줄였는데 냉각 효율 80%를 유지하면
가성비가 좋다."** — 이 문장이 모든 실험의 판정 잣대다.

## 2. 실험 3종과 우선순위

| # | 실험 | 통제 변인 | 핵심 질문 |
|---|---|---|---|
| **1** | **방열판 면적·분할** — 통짜 하나 vs 작은 조각 여러 개 | 표면적 동일 | 통째로가 답인가, 발열 지점에만 붙이는 게 가성비인가 |
| **2** | **매개체(TIM)** — 그리스 A/B/혼합/카본시트·그래핀 | 나머지 전부 | 어떤 TIM이, 얼마나, 어떻게 발라야 좋은가 |
| **3** | **냉각 시스템 위치** — 팬 유무·개수·배치 | 폐쇄 구조 필요 | 데이터센터식 능동 냉각의 최적 배치 |

### 교수님 권고 — 순서는 **3번 먼저, 그 안에서 1번**

이유가 실용적이다: 1번은 지금 개방 상태인데 3번은 **폐쇄 구조**가 필요하다. **먼저
3번에서 폐쇄 구조를 만들고 그 안에서 1번을 하라** — 순서를 바꾸면 1번을 두 번 하게 된다.

### 1번의 판정 방식(확정)

- 통짜 vs 분할의 **차이가 크면** → 통짜가 답
- **비슷하면** → 조각을 떼어 **발열 최대 지점에만** 붙이고 성능 저하·TTT를 본다
- 이때 "면적 절반인데 냉각 손실 20%면 가성비 좋다"가 합격선

### 각 실험의 배경 근거

- **1번(면적·분할)**: 방열판은 뾰족한 핀 구조라 **표면적이 넓을수록 좋다**는 건 알려져
  있다. 하지만 표면적은 곧 비용이다. 그래서 "면적 절반, 효율 80%"의 트레이드오프가 성립.
  본래 CFD + 몬테카를로/배치 시뮬레이션으로 최적화할 문제지만 현재는 제약이 있어 실측으로 간다.
- **2번(TIM)**: PC 성능 튜닝 커뮤니티에서 이미 많이 연구된 영역이다(그리스를 가운데
  점 찍고 눌러 퍼뜨리기 vs 전체 도포, 많이 vs 적게). 카본시트·그래핀·구리 페이스트 등
  매개체 종류에 따라 결과가 달라진다.
- **3번(냉각 위치)**: 데이터센터 냉각을 모사한다. 개방된 측정대를 폼보드로 **폐쇄**하고,
  팬을 여러 위치(입구·출구·측면)에 놓아 능동 냉각(액티브 랙 시스템)을 만든다. 본래
  CFD로 기류 순환을 모델링할 문제. **부하에 따라 팬 RPM을 바꾸는** 시나리오까지 포함.

## 3. 측정 방법 — 교수님 제시 절차

1. 열화상에서 **스팟 온도** 추출
2. 같은 시점의 **라즈베리파이 내부 온도를 페어로** 수집
3. 특정 온도(예: 24℃)까지 **완전히 냉각 후** 시작 (직전 잔열 제거)
4. **1~2초 간격** 촬영, 80℃ 도달까지 → 타임스탬프로 시간 산출
5. **30회 반복** → 평균 + 표준오차

> "해석은 하루 이틀이면 된다. 그 전까지 다양하게 실험을 돌리는데, **통계적 유의성을
> 얼마나 가져갈 것이냐**가 이슈다."

측정 장비 구성: 서포터 판 위에 열화상 카메라, 그 아래 라즈베리파이. 폼보드는 학교에서
구입해 **큐브 격자**로 만들어 팬 위치를 옮겨가며 실험. 동일 팬 최소 2개 필요.

## 4. 액체 냉각 질문에 대한 답 (참석자 6)

- **우주·해저 데이터센터는 "사기"** — 절대영도가 있어도 열을 전달·순환시킬 매개체가
  없으면 무의미
- **액침 냉각은 진짜** — 버티브 홀딩스 주가가 1년에 300~400% 상승
- **다만 고교 레벨에서는 비추천** — 용매가 발암물질일 수 있어 안전 문제

## 5. 시뮬레이터와 직접 얽히는 것 — 미팅 논의 ↔ 코드 현황

미팅에서 나온 논점들이 이미 만들어 둔 시뮬레이터와 어떻게 연결되는지, 그리고 **무엇이
이미 코드로 구현됐고 무엇이 남았는지**를 함께 정리한다.

### ① 관측된 온도 출렁임의 정체 = 스로틀링 (부하 아님) ✅ 모델이 이미 예측

참석자 2: *"80도 찍고 내려가고 또 찍고, 피크 타이밍이 균일하지 않다"* → *"발열이 균일한
소스(니크롬선)로 바꿔야 하나?"* — **바꿀 필요 없다.**

- 참석자 4가 **약 8초 간격**으로 이미지를 처리한다고 했다.
- 라즈베리파이 시정수 τ는 무냉각 97.5초, 방열판 58.5초. **8초는 τ의 약 1/10이라 열용량이
  전부 평균해버려 온도를 흔들 수 없다.**
- 즉 보이는 진동은 태스크 주기가 아니라 **펌웨어 거버너의 히스테리시스**다 — 85℃에서
  걸리고 조금 식으면 풀리는 것을 반복.
- 모델이 이미 예측한다: Pi5 무냉각 25℃ 기준 **30분에 약 37회, 지속시간(TED) 중앙값 14초**.

**균일하지 않은 게 정상이고, 그 자체가 측정 대상**이다(TED 분포). 니크롬선으로 바꾸면
교수님 지적대로 "AI 데이터센터" 의미가 사라진다.

### ② 예측 냉각(PTM) — 교수님이 직접 언급 🔶 제어기만 남음

> "로드가 크지 않은데 팬이 항상 돌 필요는 없다 — **예측 프리딕티브 쿨링**"

- 학생 제안 중 유망하다고 짚었던 그것.
- **부하 패턴(`AiLoadProfile`)과 열 모델이 이미 있으니 제어기만 만들면 된다.**
- 목표 함수: "스로틀링을 막으면서 **총 전력이 최소**가 되는 팬 RPM" (→ ⑥번 팬 전력 필요)

### ③ 새 평가 지표 — 온도 안정성(진폭) ✅ 2노드 모델로 구현됨

> "온도가 출렁이면 **부품 수명이 줄어든다**"

- 지금까지 없던 평가 축이다. 피크 온도·TTT 외에 **온도 진폭**을 지표로 추가.
- **이미 코드에 있다**: `HeatsinkMass`(2노드 열모델). 방열판을 독립된 열 덩어리로 다뤄
  **질량이 클수록 피크를 흡수해 진폭이 작아지는** 효과를 계산한다.
- 이 모델의 핵심 성질: 정상상태는 1노드와 **완전히 동일**(`R_ja = R_int + R_hs`),
  달라지는 건 **과도응답(진폭)뿐**. 그래서 하위호환이면서 진폭 질문에 바로 답한다.
- **이것이 1번 실험(면적·분할)의 물리적 근거**다 — 열저항이 더 나쁜(작은) 방열판이라도
  질량으로 피크를 눌러 이길 수 있다는 역전 현상을 예측한다.

### ④ 열화상 vs 내부 센서 간극 🔶 R_jc 실측으로 검증 가능

- 내부 70~80℃ vs 열화상 60℃ 차이 확인됨. 교수님도 **AI 기반 캘리브레이션 보정**을
  후속 이슈로 언급.
- 이 간극이 곧 **`P × R_jc`** (다이→케이스 열저항). 실측으로 **`R_jc`를 역산**할 수 있다.
- 2노드 모델의 내부 저항 `R_int`가 바로 그 값이라 **모델 검증에 직접 쓰인다.**

## 6. ⭐ 핵심 미해결 — 팬 전력 모델이 없다

팬은 단순 냉각 수단이 아니라 **역할이 셋**이고, 그게 연구 질문의 심장이다.

| 역할 | 내용 |
|---|---|
| ① 냉각 수단 | 열저항을 낮춤. Pi5 무냉각 6.5 → 방열판 3.9 → **팬 2.6 K/W** |
| ② **비용 변수** ⭐ | RPM↑ = 전력↑ = 전기세. **교수님이 미팅 맨 처음 꺼낸 것** |
| ③ 제어 대상 | PTM의 액추에이터 — "로드가 크지 않은데 팬이 항상 돌 필요 없다" |

**②가 없으면 이 연구가 성립하지 않는다.** 팬이 공짜면 무조건 최대로 돌리는 게 답이니까.

### 문제: 지금 모델에 ②가 없다

현재 전력 계산(`ThermalSimulator`):
```java
double powerW = p.idlePowerW() + p.dynamicPowerW() * util * clockRatio;  // SoC 전력만
energyJ += powerW * dt;
```

**팬 전력이 어디에도 없다.** `fanRpm`은 풍속 추정(열저항 낮추기)에만 쓰이고 소비전력에는
반영되지 않는다. 그래서 지금 모델에 "가성비 최적 조합"을 물으면 **항상 팬 최대**라고
답한다 — 비용이 0이니까. 연구 결론이 나와야 할 지점에서 모델이 반대를 가리킨다.

### 필요한 것

```
P_총 = P_SoC + P_팬(RPM)
```

팬 소비전력은 대략 **RPM의 3승에 비례**(팬 법칙)한다. RPM을 2배 올리면 전력은 8배인데
냉각 효과는 훨씬 완만하게 좋아진다. **이 비대칭이 "적정 수준에서 멈추는 게 낫다"의
물리적 근거**다.

이걸 넣어야 비로소 답할 수 있다:
> 스로틀링을 막으면서 **총 전력이 최소**가 되는 팬 RPM은?

이것이 교수님의 지속가능성 결론이자 PTM의 목표 함수다. 실측 팬 사양(정격 전력·RPM)만
있으면 되고, 없으면 문헌값으로 시작해 나중에 캘리브레이션할 수 있다. 넣어두면 **3번 실험
(팬 위치·개수) 결과를 바로 가성비로 환산**할 수 있다.

## 9. 다음 액션 (우선순위)

1. **팬 전력 모델 추가** (`P_총 = P_SoC + P_팬(RPM³)`) — 이게 없으면 가성비 결론이 안 나온다
2. **3번(폐쇄 구조) 세팅 → 그 안에서 1번(면적·분할)** — 교수님 권고 순서
3. **온도 진폭을 정식 지표로** — 2노드 모델이 이미 계산하니 결과지·비교표에 노출
4. **PTM 제어기** — 팬 전력 모델이 들어온 뒤 목표 함수(총 전력 최소)로 구현
