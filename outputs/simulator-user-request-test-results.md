실행일: 2026-10-28. 대상 계획: `simulator-user-request-tests.md` 10장의 빠른 1차 점검 18개.

## 실행 방법

- 사례마다 새 LLM 에이전트(Claude, general-purpose)가 사용자 비서 역할을 했다. 에이전트는 브로커(8089)와 시뮬레이터 MCP 응답만 근거로 삼았고, 저장소 파일은 읽지 않았다.
- 사용자 답은 미리 정한 대본에서 가져왔다. 대본 값은 각 장의 "정상 사례 기본 조건"이다. 대본에 없는 질문에는 "기본값으로 해줘"로 답했다.
- 에이전트는 시나리오가 UNCONFIRMED 가 되면 멈췄다. 확인 화면 승인과 실행은 사람 역할로 테스트 실행자가 했다. 승인은 `POST /api/scenarios/{id}/confirm`, 실행은 `run_scenario_by_token` 으로 했다.
- 서버: 브로커 8089, 장량동 8090, 행정동 8091, 주차장 8092(인증키 있음), 민원 창구 8093.
- 장량동 사례 B02·J01·B12 는 1차에서 막혔다. 문서의 기본 조건에 기본값 없는 필수값 "청소차 적재 몫(routeAvailableCapacityKg)"이 없었기 때문이다. 테스트 실행자가 "5톤 정격 5000kg"을 대본에 넣어 다시 돌렸다. 아래 표는 재시험 결과다.
- 근거 파일: 대본은 `scratchpad/reqtest/requests5.json`, 에이전트 기록은 `runs/UT-*.json`, 실행 결과는 `runs/exec-*.json` 이다. 모두 이 세션의 임시 폴더에 있다.

## 발견한 결함·명세 불일치

1. **장량동 적재 몫 명세 불일치.** `routeAvailableCapacityKg` 가 템플릿에는 기본값 없는 필수값이다. 그런데 `run_waste_simulation` 설명에는 "미입력 시 차종 정격용량"으로 되어 있다. 테스트 계획의 정상 조건에도 이 값이 없다.
2. **장량동 템플릿에 없는 조건.** 테스트 계획의 "수거장 30kg·민원 기준 적재율 0.8"은 템플릿 질문 항목이 아니어서 시나리오로 정하거나 확인할 수 없다. 이번에는 서버 기본값과 값이 같아 영향이 없었다.
3. **브로커 문구 매칭이 엄격하다.** "원룸 건물 4동", "공영주차장 4곳"(공간 규모), "창구 3개와 4개 비교", "목록 조회"(목적)가 모두 ADJUST_REQUEST 를 냈다. 매개변수 값을 환경 조건에 넣었을 때도 마찬가지였다(A08). 18개 중 9개에서 질문이 1회 늘었다.
4. **비교 없는 단일 실행 경로가 없다.** build_scenario 가 비교 변수를 요구해서, C09·P06 에서 에이전트가 값 하나짜리 비교로 우회했다.
5. **단위 표기 불일치.** 장량동 residentsPerBuilding 은 질문이 "세대"인데 실제 값은 사람 수로 쓰였다.
6. **표준데이터 중복 표시.** 같은 주차장이 제공기관별 관리번호 둘로 나온다(예: 죽도 공영주차장). 응답도 37~57KB로 크다.
7. **지역명→시군구 코드 변환 도구가 없다.** A07·A08 에서 에이전트가 자체 지식으로 코드를 넣었다.
8. **결과 지표 설명 부족(O06).**
   - 주차 giveUpRate 분모는 요금 때문에 오지 않은 차량을 뺀 수로 보인다. 예: 89.24/(900−180.36)=0.124. 이 분모가 결과에 설명돼 있지 않다.
   - allGiveUps 와 allReneges 는 하루가 아니라 기간 합계인데, 단위 표기가 없다.
   - hourlyMeanWait 는 시작 시각 표기가 없다.
9. **브로커 등록 목록에 꺼진 서버가 남아 있다.** 실행하지 않은 `district-waste-sim`(가상)과 `water-leak-sim` 이 list_candidates 에 나왔다. B01 은 이번 범위가 아니라 확인하지 않았다.

## 이번에 확인하지 않은 것

- 기본 사례 86개 중 나머지 68개, 추가 지원 범위, 숫자 경계값, 운영 장애(O01~O05·O08)는 실행하지 않았다.
- 반복은 3회로만 했다. 결과의 방향성은 합격 기준이 아니어서 판정에 쓰지 않았다.
